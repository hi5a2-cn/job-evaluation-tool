# 验证指南：003 HR 沟通助手 + 我的岗位库改版

> 用途：证明 003 功能端到端可用。
> 默认自动化测试不联网、不需要 API Key、不打开真实浏览器（原则 VIII）。
> 第 3 节的真实验证需要人工显式进行，覆盖 SC-001 至 SC-013 以及 V6、V7、V8 实验项。

---

## 0. 前置条件

- macOS，Python 3.12+（由 `uv` 管理），Node 22+（仅用于运行插件纯函数测试，无构建步骤）。
- Chrome 稳定版（开发者模式加载 `extension/` 目录）。
- 真实验证时：DeepSeek API Key 存放在 `~/Library/Application Support/Jet/.env`（数据目录内，禁止提交进 Git）。

---

## 1. 自动化测试（无网络、无 Key、无浏览器）

### 后端单元与集成测试 (pytest)
```bash
uv run pytest tests/
```

### 插件纯函数测试 (node --test)
```bash
node --test extension/tests/*.test.js
```

### 必须通过的关键测试场景覆盖：

| 测试场景 | 覆盖验收标准 | 验证要点 |
|---|---|---|
| **隐私脱敏纯函数** | SC-002, SC-003 | 纯函数输入包含 HR 姓名、我方姓名、姓+称呼（如刘女士）、手机号、微信号、邮箱，脱敏输出中上述信息出现次数为 0；`bodyType=16` 与 `item-system` 被剔除；`bodyType=7` 卡片仅留脱敏文字 |
| **防篡改哈希强比对** | SC-001, SC-002 | 客户端传入的 `prompt_hash` 与服务端脱敏计算出的 SHA-256 不一致时，服务端返回 400 且 0 次大模型调用 |
| **未同意与撤回拦截** | SC-001 | 未同意或已撤回状态下，调用生成接口返回 403，发往外部模型的请求数为 0 |
| **经历条目编号校验** | SC-006 | 大模型返回引用了不存在经历编号的话术被完全丢弃；全部丢弃时返回 422；合法引用的条目编号保留在来源中，话术正文无标注 |
| **问题去重过滤** | SC-005 | 当前聊天已加载消息已提及、或 HR 实际情况中已包含答案的问题，不出现在建议提问列表中 |
| **每日额度事务预占与上限** | SC-004, SC-008 | 每日上限设为 2 时，并发 3 次生成请求：恰好 2 次成功插入 `purpose='assist'` 记录，第 3 次返回 429；`llm_calls` 记录无聊天与话术正文 |
| **岗位库「全部岗位」并集** | SC-009 | 分别插入仅有状态、仅有判断、仅有 HR 记录的岗位，「全部岗位」数量严格等于去重并集总数 |
| **跨版本搜索与转义** | SC-010 | 搜索关键词含 `%`、`_` 时正确转义字面匹配；搜索仅存在于历史版本的职位名能准确命中；超过 200 条时给出 `total_matches` |
| **HR 记录空提交校验** | SC-011 | 岗位库提交纯空白 HR 记录时，前端禁用且服务端报错，数据库保持不变 |
| **状态就地修改标注** | SC-012 | 状态修改后行留在原位，显示移出标注；改回原状态标注消失；取消状态标注移出 |

## 3. 真实页面验证步骤 (人工验证清单)

### 3.1 隐私与同意验证 (SC-001, SC-002, SC-003, V6, V7)

| 步骤 | 操作 | 期望结果 |
|---|---|---|
| **P1** | 撤回同意后，在 BOSS 聊天页打开侧边栏，点击"生成"按钮 | 侧边栏立即弹出数据发送同意页面，展示字段清单和已脱敏文本预览；此时检查后端日志或抓包，发给 DeepSeek 的请求数为 0 (SC-001) |
| **P2** | 仔细核对同意页中的脱敏文本预览 | (a) HR 姓名与用户本人的姓名均已被剔除；<br>(b) "刘女士/王经理"等"姓+称呼"写法已被剔除；<br>(c) 双方电话、微信号、邮箱已被剔除 (SC-002)；<br>(d) **[V6 验证]** 检查我方姓名是否取自 `userInfo.name` 并被成功脱敏；<br>(e) **[V7 验证]** 若聊天中有 `bodyType=7` 请求卡片（如附件简历），验证卡片文字已脱敏呈现，而竞品 PK 卡片（`bodyType=16`）与撤回等系统消息完全不存在 (SC-003) |
| **P3** | 点击同意页的"取消" | 同意页关闭，不向 DeepSeek 发出任何请求 (SC-001) |
| **P4** | 再次点击"生成"并在同意页点击"同意" | 本机保存同意记录，开始正式调用大模型生成话术 |
| **P5** | 前往插件设置页点击"撤回同意" | 设置页显示同意已撤回；返回聊天页再次点击"生成"，重新弹出同意页 (SC-001) |

### 3.2 话术生成、语气规则与经历引用 (SC-004, SC-005, SC-006, SC-007, SC-013, V8)

> 默认打开聊天即自动生成（设置页"打开聊天自动生成"开关，默认开启，FR-067）；只有关闭该开关后，才需要手动点击侧边栏的「生成沟通建议」按钮（2026-09-28 更新）。

| 步骤 | 操作 | 期望结果 |
|---|---|---|
| **G1** | 在设置页维护 2 条「我的经历素材」（如"负责华南渠道，拓展 10 家代理商"） | 保存成功，实时字数正确 |
| **G2** | 打开一个 **HR 尚未回复** 的聊天（仅有自动打招呼），等待自动生成（"打开聊天自动生成"关闭时点「生成沟通建议」） | 判定为"开场白"，展示判定的依据消息；顶部显示"这是给 [公司] · [职位] 的建议"；输出 2 个语气版本话术（每条 ≤ 50 字）；下方来源说明标注引用的经历条目编号（正文无编号） (SC-005, SC-006) |
| **G3** | 打开一个 **HR 最后说话** 的聊天，等待自动生成（"打开聊天自动生成"关闭时点「生成沟通建议」） | 判定为"建议回复"，给出 2 个版本回复及最多 3 个建议问 HR 的问题；聊天中 HR 已回答的问题不出现在问题列表中 (SC-005) |
| **G4** | 打开一个 **我最后说话、HR 尚未回复** 的聊天，等待自动生成（"打开聊天自动生成"关闭时点「生成沟通建议」） | 侧边栏明确提示"正在等 HR 回复"，不生成回复话术，只给出建议要问 HR 的问题 (FR-012) |
| **G5** | 在侧边栏结果展示状态下，在 BOSS 左侧切换到另一个聊天会话 | 侧边栏旧结果 100% 立即清空，提示"已切换到新的聊天，请重新生成"，无法继续复制旧内容 (SC-007) |
| **G6** | 打开一个岗位库中不存在、无 Jet 判断的历史聊天，等待自动生成（"打开聊天自动生成"关闭时点「生成沟通建议」） | 界面显眼标注"这个岗位没有 Jet 判断"，正常生成话术，且话术或问题中包含主动确认岗位职责或销售成分的提问 (FR-011) |
| **G7** | 查看本机 SQLite `llm_calls` 表记录 | 出现 `purpose='assist'` 记录，记录了 model、Token、费用；检查该行各字段，绝对无任何聊天或话术文本 (SC-004) |
| **G8** | **[SC-013 用户验收]** 在 3 个真实 BOSS 聊天中实测生成 | 用户逐条审核：判定类型准确；每次至少有 1 个版本可直接用或稍改可用；检查语气规则效果（称呼用您、无长客套句、无反问句等）并在 rules 文件中微调 |
| **G9** | **[V8 真实页面切换验证]** 连续切换 5 个聊天；生成后切换聊天再切回、再点复制 | 连续切换 5 个聊天，每次侧边栏都清空；生成后切换聊天再切回、再点复制，行为符合 FR-005 (V8, FR-005) |
| **G10** | **[V8 复制防错核对]** 生成后在另一个聊天里点旧结果的"复制"（如界面允许出现这种情况） | 点击复制被拒绝，并提示"已切换到新的聊天，请重新生成" (V8, FR-005) |

### 3.3 每日上限控制 (SC-008)

| 步骤 | 操作 | 期望结果 |
|---|---|---|
| **L1** | 在数据目录 `.env` 中设置 `JET_DAILY_ASSIST_LIMIT=1`，重启 `jet serve` | 服务启动加载上限为 1 |
| **L2** | 在聊天页生成一次（自动生成，或开关关闭时点「生成沟通建议」）并成功 | HR 沟通助手卡片中"沟通建议：今日已用 X / 上限 Y"的已用次数加 1（FR-072） |
| **L3** | 再次点击生成按钮 | 侧边栏直接提示"今日生成次数已用完"，不发出外部网络请求，不排队 (SC-008) |

### 3.4 岗位库改版与交互 (SC-009, SC-010, SC-011, SC-012)

| 步骤 | 操作 | 期望结果 |
|---|---|---|
| **M1** | 打开"我的岗位库"独立标签页（`myjobs.html`） | 标签栏最前面显示「全部岗位」，悬停显示说明提示："有状态、判断过或记过 HR 说的话的岗位"；默认选中「已标记」（若无则默认「最近看过」） (SC-009) |
| **M2** | 检查各岗位卡片上 HR 实际情况的展示 | 每行直接显示 HR 告知的内容，最多显示两行，超出自动截断为"…"；点"展开"显示全文（≤ 200 字）；未记录的显示"未记录" |
| **M3** | 点击某行 HR 实际情况的"修改"入口，清空文字或输入纯空格后查看保存按钮 | 保存按钮被禁用不可点击，并提示"清空请到岗位卡片操作"；刷新后原记录内容保持不变 (SC-011) |
| **M4** | 修改 HR 实际情况为一段新文本并保存 | 页面就地更新，刷新后确认保存至本机数据库 |
| **M5** | 勾选顶部的「只看有 HR 记录」 | 列表仅显示有 HR 实际情况的岗位；标签栏每个标签旁的数字更新为"该状态下有 HR 记录的岗位数" |
| **M6** | 在搜索框输入关键词（如特定公司名、HR 说过的词汇、包含 `%` 或 `_`） | 结果精准匹配；匹配项包含历史版本的职位名；若结果超过 200 条，列表上方明确提示"只显示了前 200 条，共 N 条"；列表严格按最近更新时间倒序排列 (SC-010) |
| **M7** | 在「收藏」标签下将某行状态改为「已投递」 | 该行留在原位不跳动，按钮变为已投递，行上标注"已改为 已投递，切换标签或刷新后移出本列表"，标签数量同步更新 (SC-012) |
| **M8** | 在同一行重新点击改回「收藏」 | 移出标注立即消失，该行恢复正常显示 (SC-012) |
| **M9** | 点击取消状态 | 该行留在原位，标注"已取消状态，切换标签或刷新后移出本列表"；切换标签后该行移出 (SC-012) |
