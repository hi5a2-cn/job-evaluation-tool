# 验证指南：002 BOSS 只读插件 + 本机判断

> 用途：证明功能端到端可用。实现细节见 `tasks.md`；接口见 [contracts/](contracts/)；表结构见 [data-model.md](data-model.md)。
> 默认测试不联网、不需要 API Key、不打开真实浏览器（原则 VIII）。第 3 节的真实验证需要人工显式进行。

## 0. 前置条件

- macOS，Python 3.12+（由 `uv` 管理），Node 22+（只用来跑插件的单元测试，插件本身不需要构建）
- Chrome（开发者模式加载未打包扩展）
- 真实验证时：大模型 API Key 放在 `~/Library/Application Support/Jet/.env`（数据目录内，不在仓库里）

## 1. 自动测试（无网络、无 Key、无浏览器）

```bash
uv run pytest
```

```bash
node --test extension/tests/*.test.js
```

必须覆盖并通过的场景：

| 场景 | 对应要求 |
|---|---|
| 列表 15 条入库 → 15 个岗位、0 次大模型调用、每条 `list_only` | US5、SC-005、FR-017 |
| 同一岗位同内容连发 5 次 → 1 个岗位、1 个版本、判断最多 1 次 | FR-004、FR-021、SC-002 |
| 薪资变化 → 新版本 + 旧判断 `stale.job_changed = true`，未自动重判 | FR-011、FR-022 |
| 修改画像 → 旧判断 `stale.profile_changed = true` | US1-3 |
| 规则：城市不符 / 月薪上限低于底线 / 命中不接受词 → `unfit, source=rule`，0 次调用 | FR-018 |
| "银⾏"（康熙部首）匹配关键词"银行"；"深圳市"匹配"深圳"；原文不变 | FR-019、Edge Case |
| 薪资不可见 → 不按薪资排除；显示"薪资不可见" | FR-013 |
| 额度 = 2，并发 5 个通过粗筛的岗位 → 恰好 2 次调用，3 个 `quota_exhausted` | FR-023、SC-003 |
| 假模型超时 / 返回非 JSON → `failed`，计入额度，不是"不适合" | Edge Case |
| 启动时把遗留 `running` 改成 `interrupted` | Edge Case |
| 无令牌 / 令牌错 / Origin 是普通网页 → 401 / 403 | FR-007 |
| 所有个人表无主人记录数 = 0 | SC-008 |
| 测试结束后真实数据目录没有新文件（自动检查，失败即判红） | 原则 VIII |
| 插件：`readBossPage` 对保存的脱敏页面样本输出期望结构；缺字段 → `ok=false` | FR-006 |
| 插件：每种 Jet 响应 / 连接错误 → 正确的 `view_state`，没有一种错误显示成「不建议投」（即 `status = done` 且 `verdict = skip`） | FR-026、SC-004 |

## 2. 本机启动与配对

```bash
uv run jet serve
```

期望：终端显示 `Jet listening on http://127.0.0.1:47615`，数据目录路径，今日额度。

```bash
curl -s http://127.0.0.1:47615/v1/health
```

期望：`{"service":"jet","api":1,...}`。

```bash
uv run jet pair
```

期望：显示 6 位配对码。在 Chrome 打开 `chrome://extensions` → 开发者模式 → 加载 `extension/` 目录 → 打开插件设置页 → 填入配对码 → 显示"已配对"。

## 3. 真实页面验证（人工，结果写进 research.md，标 FACT / NOT VERIFIED）

| # | 操作 | 期望 |
|---|---|---|
| R1 | 不设画像，打开 BOSS 搜索列表页，点开一个岗位 | 详情旁显示"请先设置画像"；`jet stats` 显示岗位已入库、调用 0 |
| R2 | 设置画像后点开 3 个不同岗位 | 各自 10 秒内出现结论或明确状态（SC-001） |
| R3 | 再点开 R2 中的一个 | 1 秒内显示原结论；今日调用次数不变 |
| R4 | 不点开任何岗位，只打开一个 15 条的列表页 | 15 个岗位 `list_only`；调用 0 |
| R5 | 向下滚动触发"加载更多"（若页面有） | 新出现的岗位入库（目前 NOT VERIFIED，实测记录） |
| R6 | 退出 BOSS 登录后打开列表页 | 记录薪资是否为空；为空时显示"薪资不可见"（目前 NOT VERIFIED） |
| R7 | 关闭页面标记开关后刷新 | 页面上 `[data-jet]` 元素为 0；侧边栏列出本页已判断岗位 |
| R8 | 停掉 `jet serve` 后点开岗位 | 显示"Jet 未运行"，没有任何结论 |
| R9 | 单独打开一个 `/job_detail/` 页面 | 显示"此页暂不支持读取" |
| R10 | 把每日上限设为 1，点开 2 个通过粗筛的新岗位 | 第 2 个显示"今日判断额度已用完"，不是"不适合" |

## 3b. 判断质量（US7）

| # | 操作 | 期望 |
|---|---|---|
| R11 | 启动新版 `jet serve` | 终端提示已从旧结构迁移，数据目录出现 `jet.db.bak-…` 备份；旧岗位、旧判断、配对都还在 |
| R12 | 设置页填"工作内容偏好""我的背景"并保存 | 显示"已保存（版本 N）"；旧判断标"可能过时（画像已变）" |
| R13 | 点开"银行合作产品运营助理"这类岗位并重新判断 | 卡片先显示事实（白话职责、工作类型、销售成分、经验门槛、加班信号，每项附原句），再显示建议与推导；工作类型不是"运营"，销售成分为中或高 |
| R14 | 结论为"可以一试"或"需要确认"的岗位 | 卡片显示 2–3 个"建议问 HR"的问题；可填写"HR 说的实际情况"并保存、修改、清空；标注区为可选 |
| R15 | `jet eval export-jobs` → Antigravity 参考标注 → `jet eval import-reference` → `uv run jet eval run` | 报告注明"模型参考标注，非人工"及来源构成；输出 A/B/C/D 各组合的事实准确率（工作类型按大类）、总体结论一致率、误判为可投次数、引用未找到率、费用；`jet stats` 今日调用次数不变 |
