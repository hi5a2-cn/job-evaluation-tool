### 提示词与输出格式（Decision）

- 系统提示词固定（放在最前面以命中缓存），画像其次，岗位最后。
- 要求模型只返回 `{"verdict":"fit|unfit","reasons":["…","…"]}`，理由 ≤ 3 条、每条 ≤ 40 字。
- 解析失败（非 JSON、字段缺失、verdict 不在两值内）→ 判断记为"判断失败（返回无法解析）"，不猜。
- 超时 20 秒；网络错误 / 429 / 5xx 最多重试 2 次（指数退避），**每次重试都算一次调用、都占额度**（保守，满足 SC-003）。

## §2 本机 Jet 的实现技术（已决定：FastAPI + uvicorn，手动启动）

| 方案 | 优点 | 缺点 |
|---|---|---|
| **FastAPI + uvicorn（推荐）** | 请求 / 响应用 pydantic 定义，契约即代码；自带 TestClient，接口测试不用起真实端口；asyncio 后台任务方便；社区成熟 | 多两个依赖 |
| 标准库 `http.server` | 零依赖 | 要自己写路由、校验、并发；测试麻烦；后台任务要自己管线程 |
| Flask | 熟悉度高 | 同步模型，后台判断要另起线程池；没有内置数据校验 |
| 用 Node 写 Jet | 与插件同语言 | 违反 constitution 附加约束（本机 Jet 为 Python） |

- **Decision**：Python 3.12+，`uv` 管理依赖，FastAPI + uvicorn，标准库 `sqlite3`（不引入 ORM；表少、事务要精确控制）。httpx 调大模型（与 jet-demo 相同思路）。
- **启动方式**：第一版手动 `uv run jet serve`（在终端里跑，关掉终端就停）。开机自启（launchd）暂不做，以后再说（用户 2026-09-24 决定）。
- **后台判断**：进程内一个 asyncio 队列 + 1 个工作协程（串行，天然限流）；内存里维护 in-flight 集合做合并；数据库部分唯一索引兜底（见 data-model.md）。进程启动时把遗留的 `running` 改为 `interrupted`。
- **端口**：默认 47615（不常用端口，避免和开发服务器冲突），只绑定 `127.0.0.1`。

### 插件 ↔ Jet 怎么配对

- **Decision**：一次性配对码 → 长期令牌。
  1. 终端 `uv run jet pair` 显示 6 位数字码（5 分钟过期，最多试 5 次，只在内存里）。
  2. 插件设置页输入 → 后台 service worker `POST /v1/pair`。
  3. Jet 记下请求的 `Origin`（`chrome-extension://<扩展 ID>`），生成 32 字节随机令牌，只把 SHA-256 存进数据库，明文令牌返回一次。
  4. 插件把令牌存在 `chrome.storage.local`（本机 Chrome 配置目录，不进 Git）。
  5. 之后每个请求：`Authorization: Bearer` + `Origin` 都必须对上。
- **Rationale**：只监听 127.0.0.1 挡住了外部机器，但**本机任意网页都能向 127.0.0.1 发请求**；Origin + 令牌两道检查挡住网页。配对码需要在终端里看到，等于"用户本人确认"。
- **Alternatives**：
  - 固定写死的共享密钥 —— 会进仓库或要手动复制长串，否决。
  - Chrome Native Messaging（插件通过 stdio 启动本机程序）—— 不需要端口和配对，但 Jet 的生命周期被插件绑住，而且 constitution 已约定"本机 HTTP 接口"，否决。
  - 只校验 Origin 不要令牌 —— 本机其他程序可以伪造 Origin 头，否决。
- **第二阶段（朋友加入）**：同一套配对，令牌对应不同 `user_id`；接口不变。

## §4 页面读取方式

- **Decision**：service worker 用 `chrome.scripting.executeScript({world: "MAIN", func})` 一次性读取，内容脚本（ISOLATED）用 MutationObserver 只负责"页面变了"的通知。详见 contracts/page-reader.md。
- **Rationale**：Vue 实例（`el.__vue__`）只在页面 JS 环境可见（FACT：实验插件必须用 `world: 'MAIN'` 才读得到）。结果直接回到插件，不经过页面能看到的 `postMessage`。
- **Alternatives**：常驻 MAIN world 脚本 + 定时轮询（页面环境里常驻代码，被察觉面更大，否决）；读 DOM 文字（薪资是私有字体、会混入推荐内容，违反原则 V，否决）；拦截页面网络请求（需要包装 fetch/XHR，违反原则 IV，否决）。
- **风险（INFERENCE）**：MAIN world 执行的函数理论上可被页面察觉；实验插件同样做法未见异常（1 次记录），由 SC-007 一周观察兜底。
- **待办**：列表数据里还有公司名、经验、学历等字段（实验插件未读取）。本版 spec 实体没有公司名，不加；如需按公司过滤，开 Issue。
