# Feature Specification: BOSS 岗位只读插件 + 本机判断（第一阶段：本人、本机）

**Feature Branch**: `002-boss-readonly-extension`

**Created**: 2026-09-24

**Status**: Draft（2026-09-24 修订：新增 US7 判断质量，依据真实页面试用反馈）

**Input**: User description: "功能 002：BOSS 岗位只读插件 + 本机 Jet 判断（第一阶段：本人、本机）。遵循 constitution v2.0.0。……（完整描述见本次 /speckit-specify 输入）"

## 概述

用户自己在 Chrome 里正常浏览 BOSS 直聘。插件自动读取当前页面**已经加载**的岗位信息，不向平台发任何请求，交给本机 Jet。
Jet 按用户画像判断岗位是否适合。适合和不适合的岗位都进入公共岗位库，判断结果只属于该用户。
之后用户再浏览时，页面上（或插件侧边栏里）会提醒哪些岗位已经判断过、结论是什么。

本功能取代 001（自动采集）。依据是 constitution v2.0.0 原则 III、IV、V。

### 读取可行性证据（2026-09-24，实验插件 v0.0.2，真实页面）

| 页面 | 结果 | 证据等级 |
|---|---|---|
| 搜索列表页 | 能读到当前页全部岗位：岗位 ID、职位名、薪资（明文）、城市、区域（可能为空）、是否还有下一页 | FACT（1 次记录，15 条岗位） |
| 列表页右侧详情 | 能读到：岗位 ID（与列表一致）、职位名、薪资（明文）、地点、完整职位描述 | FACT（1 次记录） |
| 列表页连续点不同岗位 | 地址栏网址不变；"换了岗位"只能靠页面数据里的岗位 ID 变化判断 | FACT（用户观察） |
| 独立详情页（单独打开的岗位页） | 按目前的读取方式读不到岗位数据；数据在哪里 | FACT（读不到，1 次记录）；数据来源 NOT VERIFIED |
| 向下滚动加载更多、未登录时薪资是否可见 | 未测 | NOT VERIFIED |
| 职位描述中的兼容字符 | 出现康熙部首等形似汉字的字符（例如"银⾏"），规范化后才等于常用字 | FACT |
| 打开浏览器开发者工具 | BOSS 页面跳到空白页（关闭插件后也会跳），与插件无关 | FACT |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 设置简单画像 (Priority: P1)

我在插件的设置页填写方向（想找的岗位类型、关键词）、城市、底线（例如最低月薪、不接受的条件）。保存后，Jet 就按这份画像判断岗位。

**Why this priority**: 没有画像就无法判断，这是其他所有判断类故事的前提。

**Independent Test**: 只做设置页和保存。打开设置页，填写并保存；关闭后再打开，内容还在；未填写时，其他地方会提示"请先设置画像"。

**Acceptance Scenarios**:

1. **Given** 从未设置过画像，**When** 我打开 BOSS 列表页并点开一个岗位，**Then** 页面提示"请先设置画像"，不做判断，也不调用大模型；岗位仍照常入库。
2. **Given** 我填写了方向、城市、底线并保存，**When** 我关闭再打开设置页，**Then** 看到的是刚才保存的内容。
3. **Given** 我修改并保存了画像，**When** 我再看之前已判断过的岗位，**Then** 这些判断标记为"可能过时（画像已变）"，不会自动重新判断。

---

### User Story 2 - 点开岗位就自动判断 (Priority: P1)

我在搜索列表页点开一个岗位，右侧出现详情。插件自动读到这个岗位的完整信息，交给 Jet 判断。几秒后，在详情旁边看到"适合 / 不适合 + 理由 + 判断时间"。这个岗位进入公共岗位库，判断结果存在我的个人数据里。

**Why this priority**: 这是主线的核心价值：读取 → 入库 → 判断 → 提醒。

**Independent Test**: 在已设置画像、Jet 在运行的情况下，点开 3 个不同岗位，每个都显示判断结果；公共岗位库中新增 3 个岗位，我的个人数据中新增 3 条判断。

**Acceptance Scenarios**:

1. **Given** 画像已设置、Jet 在运行，**When** 我在列表页点开一个没判断过的岗位，**Then** 插件显示"判断中"，随后显示"适合"或"不适合"、理由和判断时间。
2. **Given** 我连续点开不同岗位（网址不变），**When** 页面上的岗位 ID 变化，**Then** 每个新岗位都被读取；同一个岗位不会因为页面刷新或重复点击被重复读取、重复判断。
3. **Given** 一个岗位没通过规则粗筛（例如城市不符或薪资低于底线），**When** 判断完成，**Then** 结论为"不适合"，理由写明没通过哪条规则，并且不调用大模型。
4. **Given** 一个岗位通过了规则粗筛，**When** 今日大模型额度还有剩余，**Then** 调用大模型判断，并在今日调用次数里记一次。

---

### User Story 3 - 已判断过的岗位直接显示结果 (Priority: P1)

我再次点开一个判断过的岗位，直接看到之前的结论和判断时间，不再花钱判断。如果岗位内容或画像变了，会标注"可能过时"，由我决定要不要重新判断。

**Why this priority**: 控制成本（原则 VII），并且让"提醒我已判断过"这个核心需求成立。

**Independent Test**: 点开一个已判断的岗位，结果立即出现，今日大模型调用次数不变；修改画像后再点开，看到"可能过时"和"重新判断"按钮。

**Acceptance Scenarios**:

1. **Given** 岗位已判断过、内容和画像都没变，**When** 我再次点开，**Then** 显示原结论和判断时间，大模型调用次数不增加。
2. **Given** 岗位的实质内容（例如薪资、职位描述）变了，**When** 我再次点开，**Then** 公共岗位库保留旧版本；原判断标为"可能过时（岗位已变）"；不自动重新判断。
3. **Given** 判断标为"可能过时"，**When** 我点"重新判断"，**Then** 按当前画像重新判断（受今日额度限制），旧判断保留为历史。

---

### User Story 7 - 判断先讲清事实，再对照偏好；可标注、可评测 (Priority: P1)

真实页面试用发现："银行合作产品运营助理"的职责是银行营销活动策划、对接银行、配合商务，本质是营销 / 商务，却被判成"适合"，理由只是对照画像关键词打勾（"含运营""深圳符合"）。
很多时候我自己也说不清一个岗位适不适合，所以 Jet 不能只给结论：它要先讲清这份工作实际干什么（每项都引用职位描述原句），再把这些事实和我的画像逐项对照，给出"适合 / 存疑 / 不适合"的建议和推导过程。
（2026-09-25 修订）我看不懂职位描述里的坑，这正是做 Jet 的原因，所以判断质量**不能依赖我的标注**。评测的参考答案来自：HR 告诉我的实际情况（最可靠，选填）→ 我的可选标注 → 由 Gemini 3.8 Flash (High) 读职位描述做的**模型参考标注（非人工）**，我只抽查。结论为"可以一试"或"需要确认"时，卡片给出 2–3 个建议问 HR 的问题，帮我把模糊之处问清楚。

**Why this priority**: 判断是主线的核心价值；判断方式错了，入库、提醒都没有意义（原则 I）。没有评测集，就无法知道改了提示词或换了模型之后是变好还是变坏（原则 X）。

**Independent Test**: 用真实岗位（包括上面那个银行运营助理）点开详情，卡片先显示事实（白话职责、工作类型、销售成分、经验门槛、加班信号，每项附原句），再显示建议和推导；在卡片上标注事实，设置页的评测集数量增加；运行 `jet eval run`，得到各组合的事实准确率、误判为适合次数、引用未找到率和费用。

**Acceptance Scenarios**:

1. **Given** 一个职位名是"运营助理"、职责以营销活动策划和对接客户为主的岗位，**When** Jet 判断，**Then** 工作类型为"营销"或"销售"而不是"运营"，销售与客户对接成分为"中"或"高"，并列出命中的变相销售信号原句；画像不想做销售时，建议不是"适合"。
2. **Given** 任意完成的判断，**When** 我看卡片，**Then** 先看到事实部分（每项附职位描述原句，找不到的原句标"未在原文找到"），再看到"适合 / 存疑 / 不适合"和推导过程。
3. **Given** 结论为"存疑"，**When** 显示，**Then** 用黄色，不显示成"不适合"。
4. **Given** 我在卡片上标注了工作类型和销售成分（总体结论可不填），**When** 我的标注与 Jet 的事实不一致，**Then** 这条标注记为一条纠正，卡片显示"已纠正"；设置页的评测集数量加一。
5. **Given** 评测集有 15–20 条标注，**When** 我运行 `jet eval run`，**Then** 对每种组合输出事实准确率、"把不适合判成适合"次数、引用未找到率和费用；评测调用不占每日判断额度。
6. **Given** 判断提示词升级了版本，**When** 我再看旧判断，**Then** 标"可能过时（判断方式已更新）"，不自动重新判断。

### User Story 8 - 我的岗位库：收藏 / 已投递 / 不考虑 (Priority: P2)

我在卡片上把岗位标为"收藏""已投递"或"不考虑"，之后在插件的"我的岗位库"页面按状态找回它们，点开就是 BOSS 上的原岗位。没来得及收藏的岗位，也能在"最近看过"里找回。

**Why this priority**: 主线的"反馈"一步；这些状态也是以后从行为学习偏好（[Issue #3](https://github.com/hi5a2-cn/jet/issues/3)）的数据来源（本轮只记录，不学习）。

**Independent Test**: 在卡片上把 3 个岗位分别标为收藏、已投递、不考虑，再取消其中一个；打开"我的岗位库"，各筛选项数量正确，"最近看过"按最后查看时间列出 Jet 判断过的岗位；点击一行在新标签页打开 BOSS 原岗位。

**Acceptance Scenarios**:

1. **Given** 一个已判断的岗位，**When** 我点"收藏"，**Then** 按钮高亮，状态与时间保存为我的个人数据；再点"已投递"则替换为已投递；再点"已投递"则取消（无状态）。
2. **Given** 我标过若干岗位，**When** 打开"我的岗位库"，**Then** 可按 全部（标过状态的岗位）/ 收藏 / 已投递 / 不考虑 / 最近看过 筛选，每行显示职位名、公司（没读到时显示"公司未读取"）、薪资、城市、Jet 结论、HR 实际情况是否已记录、状态与时间。
3. **Given** 列表中的某一行，**When** 我点击它，**Then** 在新标签页打开该岗位在 BOSS 上的页面。这是用户点击触发的打开链接，不属于自动化，不违反原则 IV。

### User Story 4 - 列表页提醒已判断的岗位 (Priority: P2)

我浏览搜索列表时，已判断过的岗位卡片上有"适合 / 不适合"的小标记。页面标记有开关：关掉后插件完全不改动页面，改在插件侧边栏列出"本页已判断过的岗位"。

**Why this priority**: 浏览时避免重复点开已看过的岗位。依赖 US2、US3 已有判断数据。

**Independent Test**: 在有判断数据的前提下打开列表页，已判断岗位带标记；关掉开关后刷新，页面上没有任何插件添加的内容，侧边栏列出同样的岗位。

**Acceptance Scenarios**:

1. **Given** 本页 15 个岗位中有 3 个已判断，**When** 页面标记开关打开，**Then** 这 3 张卡片带有对应结论的标记，其他卡片不带标记。
2. **Given** 页面标记开关关闭，**When** 我打开列表页，**Then** 页面上没有插件添加的任何内容；侧边栏显示"本页已判断过的岗位"，共 3 个，每个都有结论和判断时间。
3. **Given** 本页没有已判断的岗位，**When** 我打开侧边栏，**Then** 显示"本页没有已判断过的岗位"，而不是空白。

### User Story 5 - 浏览列表时岗位自动入库 (Priority: P2)

我在搜索列表页看到的岗位，即使没点开，也会进入公共岗位库，标记"仅列表信息"，不判断、不花钱。

**Why this priority**: 积累公共岗位库，为以后的查看（003）和提醒打基础；不产生费用。

**Independent Test**: 打开一个有 15 个岗位的列表页，不点开任何岗位；公共岗位库中这 15 个岗位存在，都标记"仅列表信息"，今日大模型调用次数为 0。

**Acceptance Scenarios**:

1. **Given** 列表页显示 15 个岗位，**When** 页面加载完成，**Then** 这 15 个岗位进入公共岗位库（已存在的只更新），状态为"仅列表信息"，我的查看记录中各记一次"在列表页看到"。
2. **Given** 一个"仅列表信息"的岗位，**When** 我点开它的详情，**Then** 该岗位补全为完整信息，并进入 US2 的判断流程。
3. **Given** 列表数据变化（例如翻页或加载更多），**When** 出现新的岗位 ID，**Then** 只对新出现的岗位入库，不重复处理已处理过的岗位。

---

### User Story 6 - 读不到、判断不了时明确告诉我 (Priority: P2)

出现问题时，插件明确告诉我原因，不能显示成"不适合"或"没有岗位"。

**Why this priority**: 原则 IV、V："不知道"不能显示成"没有"；读不出时不能静默降级。

**Independent Test**: 分别制造"Jet 未运行""独立详情页""今日额度用完""页面数据结构变化"等情况，每种都看到对应的明确提示。

**Acceptance Scenarios**:

1. **Given** Jet 没有运行，**When** 我点开岗位，**Then** 显示"Jet 未运行"，不显示任何判断结论；Jet 启动后，再次点开该岗位即可正常处理。
2. **Given** 我单独打开一个岗位详情页，**When** 页面加载完成，**Then** 显示"此页暂不支持读取"；不入库、不判断，也不显示"不适合"或"无数据"。
3. **Given** 今日大模型额度已用完，**When** 一个岗位通过了规则粗筛，**Then** 显示"今日判断额度已用完"；岗位照常入库，规则粗筛的结果照常保存，不显示成"不适合"。
4. **Given** 页面数据结构变了、读不出预期字段，**When** 插件读取，**Then** 显示"页面无法识别"；不入库，不退回去读整页文字。
5. **Given** 读到的岗位薪资为空，**When** 入库，**Then** 薪资记为"薪资不可见"，不记为空值；判断时不把它当作低于底线。

### Edge Cases

- 同一个岗位在极短时间内被多次读到（例如快速来回点击）：只入库一次、只判断一次（原则 VI）。
- 两个浏览器标签页同时打开同一个岗位：结果一致，不重复判断。
- 大模型判断失败（超时、返回无法解析）：显示"判断失败"和原因；可以手动重试；失败不计为"不适合"。失败的调用是否占用每日额度，按实际计费调用计。
- 区域字段为空：正常入库，区域记为"未提供"。
- 职位描述含兼容字符（例如康熙部首）：规则匹配前先规范化，保证"银⾏"能匹配关键词"银行"；保存原文不改动。
- 画像里的城市与岗位城市写法不同（例如"深圳"与"深圳市"）：视为同一城市。
- BOSS 出现验证码或风控页面：插件什么都不做，也不显示错误；用户处理完、页面恢复后照常读取。
- 用户打开开发者工具导致页面跳到空白页：与插件无关，插件不做任何处理。
- 页面标记开关在浏览中途切换：已添加的标记在关闭后立即全部移除，侧边栏开始显示列表。
- Jet 在判断进行中被关闭：该岗位的状态保持"判断中未完成"；Jet 重启后可以重新判断，不留下"没有主人"的半条记录。

## Requirements *(mandatory)*

### Functional Requirements

**读取（插件）**

- **FR-001**: 插件 MUST 只读取用户当前打开的 BOSS 页面已经加载的数据；MUST NOT 向招聘平台发起任何请求；MUST NOT 导航、点击、滚动、翻页或打开新页面；MUST NOT 替换或包装页面自身的函数或属性（原则 IV）。
- **FR-002**: 插件 MUST 支持两类页面：搜索列表页（读取当前列表中的全部岗位）和列表页右侧详情（读取当前显示岗位的完整信息）。
- **FR-003**: 插件 MUST 以页面数据中的岗位 ID 变化作为"换了岗位 / 列表变了"的依据，MUST NOT 依赖网址变化。
- **FR-004**: 同一岗位的同一份内容 MUST 只发送给 Jet 一次；页面刷新或重复点击不得造成重复入库或重复判断。
- **FR-005**: 在独立详情页，插件 MUST 显示"此页暂不支持读取"，不入库、不判断。
- **FR-006**: 读不到预期字段时，插件 MUST 报告"页面无法识别"，MUST NOT 改为读取整页文字等降级方式（原则 V）。
- **FR-007**: 插件 MUST 只与本机 Jet 接口通信，且只在配对成功后发送数据；配对信息 MUST NOT 保存到代码仓库中。
- **FR-008**: 插件 MUST NOT 依赖浏览器开发者工具，MUST NOT 绕过或屏蔽平台的任何检测机制。

**入库（本机 Jet）**

- **FR-009**: 公共岗位库 MUST 以平台岗位 ID 为身份，同一岗位只存一份。
- **FR-010**: 只来自列表页的岗位 MUST 标记"仅列表信息"；读到完整详情后 MUST 升级为"完整信息"。已有完整信息的岗位再从列表页读到时，MUST NOT 降级为"仅列表信息"。
- **FR-011**: 岗位实质内容变化时（职位名、薪资、城市、职位描述之一改变），MUST 保存新版本并保留旧版本；未变化时只更新"最近读到时间"。已是"完整信息"的岗位，从列表页读到时不比较、不新建版本，只更新"最近读到时间"；内容变化以详情页为准（Issue #6，2026-09-26）。

### 指标定义

| 指标 | 数的是什么 | 按谁过滤 | 时间范围 |
|---|---|---|---|
| 今日大模型调用次数 | 实际发出且计费的大模型判断调用次数（含失败但已计费的） | 当前用户 | 本机时区的当天 0 点至今 |
| 每日上限 | 配置值（默认 150） | 当前用户 | 每天 |
| 今日剩余次数 | 每日上限 − 今日大模型调用次数，最小为 0 | 当前用户 | 本机时区的当天 |
| 本页已判断岗位数 | 当前列表页读到的岗位中，当前用户有判断记录（含"可能过时"）的数量 | 当前用户 × 当前页面 | 当前页面状态 |
| 我的岗位库各筛选数量 | 全部 = 当前用户有状态的岗位数；收藏 / 已投递 / 不考虑 = 当前状态为该值的岗位数；最近看过 = 当前用户有判断记录的岗位数 | 当前用户 | 全部 |
| 规则排除数（今日） | 今日被规则直接排除（"不建议投"）的岗位数：每个岗位只算一次，只看现在的判断（被重新判断取代的旧判断不计；2026-09-25 修订） | 当前用户 | 本机时区的当天 |
| 评测集标注数 | 当前用户的标注条数（每个岗位版本只算最新一条；可选信息） | 当前用户 | 全部 |
| 参考答案来源构成 | 某项指标中，参考答案来自用户标注的条数与来自模型参考标注的条数 | 当前用户 × 某次评测运行 | 该次运行 |
| 事实准确率（某项） | 该项 Jet 答案与标注一致的条数 ÷ 该项有标注的条数；Jet 答"存疑 / 无法判断"算不一致；工作类型只比较主要类型的大类，细分与次要类型不计入 | 当前用户 × 某次评测运行 × 某组合 | 该次运行 |
| 误判为可投次数 | 标注总体结论为"不建议投"、Jet 结论为"适合投递"或"可以一试"的条数 | 同上 | 该次运行 |
| 总体结论一致率 | Jet 四档结论与标注总体结论相同的条数 ÷ 填了总体结论的标注数 | 同上 | 该次运行 |
| 引用未找到率 | 在职位描述中找不到的引用段数 ÷ 引用总段数 | 同上 | 该次运行 |
| 评测费用 | 该次运行所有评测调用的估算费用之和（DeepSeek 按配置单价；Jev 按接口返回用量，单价未核实时只报用量） | 同上 | 该次运行 |

### Key Entities

- **公共岗位**：一个平台岗位，身份是平台岗位 ID。包括信息完整度（仅列表信息 / 完整信息）、首次和最近读到时间，以及当前版本。不属于任何个人。
- **岗位版本**：某一时刻岗位的实质内容（职位名、薪资或"薪资不可见"、城市、区域、职位描述）。实质内容变化时新增一个版本。
- **用户**：早期只有一位使用者，但所有个人数据都带用户身份。
- **画像（带版本）**：方向、城市、底线；属于某个用户。
- **查看记录**：某用户在某时间、在哪类页面上读到某岗位；属于该用户。
- **判断**：某用户对某岗位版本、在某画像版本、某提示词版本下的事实与结论（适合投递 / 可以一试 / 需要确认 / 不建议投四档；早期三档"适合 / 存疑 / 不适合"的旧判断分别按适合投递 / 需要确认 / 不建议投显示）；包括来源（规则 / 大模型）、推导或理由、时间、状态（有效 / 可能过时 / 失败 / 额度用完待判断）。属于该用户。
- **标注**：某用户对某岗位版本的事实标注（工作类型、销售成分、经验是否满足、加班信号）及选填的总体结论和备注；与 Jet 不一致即为纠正。属于该用户。构成评测集。
- **评测运行**：一次 `jet eval run` 的组合、指标和逐条结果；保存在本机数据目录。
- **大模型调用记录**：每次调用的时间、所属用户、用途（判断 / 评测）、提供方（DeepSeek / TypeSafe）、对应的判断、是否计费；判断用途用于每日上限，评测用途单独计数。
- **插件配对**：本机 Jet 与某个插件实例之间的信任关系；属于该用户。
