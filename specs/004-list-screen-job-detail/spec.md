# Feature Specification: 列表页规则粗筛 + 独立职位页被动读取

**Feature Branch**: `004-list-screen-job-detail`

**Created**: 2026-09-29

**Status**: Draft

**Input**: 唯一需求来源：`docs/drafts/feature-004-draft.md`（2026-09-28–29 用户逐条确认后定稿；本 spec 生成后该草稿删除）。依据：`experiments/boss-page-probe` 0.1 版三份（列表页 / 聊天页 / 独立职位页）与 0.2 版两份（两个不同公司的独立职位页）真实页面探测结果（2026-09-28），以及列表页入库的真实公司行业取值（2026-09-28，28 种、60 个岗位）。遵循 constitution（`.specify/memory/constitution.md` 4.0.2）。

## 概述

两件事，都只在用户自己浏览时被动进行：

1. **列表页规则粗筛**：在 BOSS 搜索列表页，用列表里已经加载的字段，按我的画像和重点排查行业名单，给每个岗位卡片加上"值得点开 / 可以跳过"的参考提示。只用规则，零费用。
2. **独立职位页被动读取**：我自己打开独立职位页（例如从聊天页点「查看职位」新开的标签页）时，Jet 读取该岗位、入库并按现有规则判断，和列表页右侧详情区一样显示卡片；读不出来就明确显示"此页暂不支持读取"。

### 与 constitution 的关系（2026-09-28 用户确认的解释）

原则 VII 写"先用规则粗筛，再对候选岗位调用大模型"，同时写"'仅列表信息'的岗位不判断、不调用大模型"。本功能的粗筛结果**只是提示，不是判断**：**不写入判断表、不给结论、不调大模型、不占额度**；画像变化时即时按新画像重算；点开岗位后仍按现有流程做完整判断。宪法不修改。

## 已确认的页面事实

### 搜索列表页（FACT，2026-09-28 探测）

- 每页 30 个岗位，页面已加载的数据中每个岗位有：职位名、公司名（品牌简称）、公司行业名称（30/30 非空）、薪资文字、城市、区域、岗位标签（2–5 个）、技能标签（0–13 个，21/30 非空）、经验要求、学历要求、公司规模、融资阶段。
- 列表数据中**没有**职位描述全文（只有点开岗位后才有）。
- 列表数据中还有招聘者姓名、头像、职务及各类令牌字段，本功能**不读取**；行业编号**不读取**。

### 独立职位页（FACT，2026-09-28 探测，两个不同公司页面结构一致）

- 地址形如 `www.zhipin.com/job_detail/<岗位 ID>.html?securityId=…`，其中岗位 ID 与列表数据、聊天会话中的岗位 ID 一致（003 spec 已记录的 FACT）。
- 页面没有可用的页面状态数据，岗位信息只能从页面上已显示的内容读取。
- 页面顶部职位信息区有职位名（页面唯一的一级标题）、薪资、城市、经验、学历；职位描述是岗位详情区的第一段正文；岗位详情区里另有"薪资说明"一段、公司区里另有"公司介绍"一段，都不是职位描述。
- 公司区的"工商信息"里有公司工商登记全称（与列表里的品牌简称不同），以及法定代表人、成立时间、企业类型、经营状态、注册资本、地址；**没有行业**。
- 页面右侧「公司基本信息」栏**有公司行业**（用户截图 FACT：显示过"文化艺术/娱乐"），但其位置未经探测确认。
- 页面上还有招聘者信息区、相似岗位与推荐岗位列表（其中的职位名、薪资属于其他岗位）。
- 聊天页顶部岗位栏的「查看职位」由用户点击后新开标签页打开该页面（用户实测 FACT）；Jet 目前在该页显示"此页暂不支持读取"。

**读取位置（探测 FACT，两页一致，供 plan 使用，实现时再用真实页面验证）**：

| 字段 | 页面位置 | 依据 |
|---|---|---|
| 职位名 | `.job-banner .info-primary .name h1` | 页面唯一的 `h1` |
| 薪资 | `.job-banner .info-primary .name span.salary` | 匹配数 1 |
| 城市 | `.job-banner .info-primary a.text-desc.text-city` | 匹配数 1 |
| 职位描述 | `.job-detail-section > .job-sec-text`（第一个） | 薪资说明在 `.detail-section-item.salary-info` 内、公司介绍为 `.job-detail-company` 内的 `.job-sec-text.fold-text`，父元素都不是 `.job-detail-section`，被排除 |
| 公司工商登记名 | `.job-detail-company .business-info-box li.company-name` | 匹配数 1 |
| 不读 | `.job-boss-info`（招聘者）、`li.company-user`（法定代表人）、`.company-address`、`.similar-job-*`、`.look-job-list` | 个人信息或其他岗位 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 列表页直接看到粗筛提示 (Priority: P1)

我在 BOSS 搜索列表页浏览时，每个还没判断过的岗位卡片上直接显示粗筛提示：公司属于重点排查行业的标"高风险行业（某行业）"，薪资上限低于我的最低月薪的标"低于薪资底线"，职位名或标签命中我"不接受条件"的标"命中不接受条件：某词"，在我"不去的城市"的标"不去的城市"。没有命中任何规则的岗位不加粗筛提示。我据此决定先点开哪些岗位、哪些可以跳过。提示不花钱、不影响我浏览，也不会自动替我隐藏或跳过任何岗位。

**Why this priority**: 列表页一页 30 个岗位，逐个点开才能判断，费时；列表数据里已有行业、薪资、标签等字段，规则就能筛出明显不合适的，零费用，直接减少无效点开。

**Independent Test**: 设好画像（最低月薪、不接受条件、不去的城市），打开 BOSS 搜索列表页，核对命中各类规则的岗位卡片是否出现对应提示、未命中的是否没有提示，并核对本机大模型调用记录与每日额度在浏览前后不变。

**Acceptance Scenarios**:

1. **Given** 某岗位的公司行业是"食品/饮料/烟酒"（重点排查行业"快消"的同义名），**When** 我打开包含它的列表页，**Then** 该岗位卡片标记显示"高风险行业（快消）"，岗位照常显示、不被隐藏。
2. **Given** 我的最低月薪为 8K，某岗位薪资为"4-6K"，**When** 列表页加载，**Then** 该岗位卡片显示"低于薪资底线"。
3. **Given** 我的不接受条件含"销售"，某岗位职位名不含"销售"但技能标签含"销售"，**When** 列表页加载，**Then** 该岗位卡片显示"命中不接受条件：销售"。
4. **Given** 某岗位薪资显示"面议"或薪资不可见，**When** 列表页加载，**Then** 不显示"低于薪资底线"（不知道不等于低于）。
5. **Given** 我修改了画像的最低月薪，**When** 我回到列表页或列表页下一次读取，**Then** 粗筛提示按新画像重算，不沿用旧结果。
6. **Given** 列表页浏览了多页，**When** 我查看本机大模型调用记录、每日额度和判断记录，**Then** 三者均没有因粗筛增加任何记录或消耗。

### User Story 2 - 自己打开独立职位页时也能入库和判断 (Priority: P2)

我在聊天页点「查看职位」，或以其他方式自己打开了独立职位页。页面加载完后，Jet 读取这个岗位的职位名、薪资、城市、职位描述和公司名，入库并按现有规则判断，页面上出现和列表页右侧详情区一样的岗位卡片（结论、状态按钮、HR 实际情况等）。之后回到聊天页，"当前岗位"区块就能显示这个岗位在岗位库里的情况和 Jet 判断。页面读不出来时，卡片明确显示"此页暂不支持读取"，不入库、不判断。

**Why this priority**: 很多聊过的岗位在搜索列表里搜不到，岗位库里没有它们的职位描述，聊天助手也就拿不到 Jet 判断（003 真实页面验证时现有聊天的岗位均不在库）。独立职位页是用户自己打开的，读取它不增加任何平台请求。

**Independent Test**: 从聊天页点「查看职位」打开独立职位页，核对页面卡片出现、岗位入库、判断完成；回到聊天页核对"当前岗位"区块显示在库；再打开一个结构不同或读不出的页面，核对显示"此页暂不支持读取"且未入库。

**Acceptance Scenarios**:

1. **Given** 一个不在岗位库里的岗位，**When** 我自己打开它的独立职位页并等待加载完成，**Then** 该岗位以"完整信息"入库，按现有规则判断，页面卡片显示判断中及结果。
2. **Given** 该岗位已从列表页入库、公司名为品牌简称，**When** 我打开它的独立职位页，**Then** 岗位内容按现有规则合并更新，公司名**不被**工商登记全称覆盖，公司行业沿用库里已有的值。
3. **Given** 该岗位库里没有公司名，**When** 我打开它的独立职位页，**Then** 公司名记为页面上的工商登记全称。
4. **Given** 页面缺少职位名或职位描述（结构变化、岗位已下线等），**When** 页面加载完成，**Then** 卡片显示"此页暂不支持读取"，不入库、不判断，也不改用读取整页文字。
5. **Given** 独立职位页入库完成，**When** 我回到对应聊天，**Then** 侧边栏"当前岗位"区块显示该岗位在岗位库中的状态与 Jet 判断。
6. **Given** 我只是在聊天页浏览、没有点「查看职位」，**When** 任意时间，**Then** Jet 不会自行打开或在后台打开任何独立职位页。

### Edge Cases

- 列表岗位公司行业为空：只按职位名、公司名关键词判断是否显示"高风险行业"提示，其余规则照常。
- 画像未设置：只显示"高风险行业"提示（它不依赖画像），其余三类不显示；不报错。
- 同一岗位同时命中多条规则：全部显示，按"高风险行业、低于薪资底线、命中不接受条件、不去的城市"的顺序。
- 已判断过的岗位：列表卡片继续显示现有判断标记，不再显示粗筛提示（判断已包含从严规则）。
- 薪资格式无法解析：不显示"低于薪资底线"。
- 重点排查行业规则文件缺失或格式错误：不显示"高风险行业"提示，其余规则照常，不报错。
- 独立职位页出现验证码或风控页：插件什么都不做（原则 V）。
- 独立职位页地址里没有可识别的岗位 ID：显示"此页暂不支持读取"。
- 同时打开多个独立职位页标签：各标签分别读取自己的岗位，互不影响。
- 独立职位页的岗位已下线：若职位名或职位描述读不到，按读取失败处理。

## Requirements *(mandatory)*

### Functional Requirements

**列表页规则粗筛（US1）**

- **FR-001**: 列表页岗位入库时，系统 MUST 按当前画像和重点排查行业名单，为每个岗位计算粗筛提示，包括四类：
  1. **高风险行业**：公司行业名称与重点排查行业名单中的行业名或其同义名相同或包含；公司行业未命中或为空时，职位名或公司名含该行业的关键词（规则文件 `keywords`，2026-09-29 用户决定）也算 → "高风险行业（行业名）"；
  2. **低于薪资底线**：薪资可见且能解析、薪资上限低于画像"最低月薪" → "低于薪资底线"；
  3. **命中不接受条件**：画像"不接受条件"中的词出现在职位名、岗位标签或技能标签中 → "命中不接受条件：词"；
  4. **不去的城市**：岗位城市在画像"不去的城市"中 → "不去的城市"。
- **FR-002**: 规则 2–4 MUST 与现有判断前的规则排除使用同一套规则与画像字段，保证职位名、薪资、城市的命中结果与点开后规则排除一致。岗位标签与技能标签只用于粗筛提示：点开后的规则排除仍只看职位名（规则版本 r3 不变，已有判断不因此变"可能过时"）；仅因标签或技能命中"不接受条件"的岗位，点开后交给大模型判断（2026-09-29 实施时发现原写法与现有规则排除矛盾，按不改变已有判断的方式修订，用户 2026-09-29 确认）。
- **FR-003**: 重点排查行业名单、同义名与职位名 / 公司名关键词 MUST 使用 002 FR-057 的同一个规则文件，每次计算时读取，改文件即生效；不提供设置界面。关键词只用于粗筛提示与判断提示词中的行业识别，不参与规则排除。（2026-09-29 修订，006 FR-010–FR-012："对哪些行业从严"改为设置页勾选项，粗筛只按用户勾选的行业给"高风险行业"提示，未勾选时不给；"不提供设置界面"作废。）
- **FR-004**: 粗筛提示 MUST 只显示在列表卡片的标记上，不做侧边栏汇总；已有判断的岗位继续显示判断标记，不显示粗筛提示；没有命中任何规则的岗位不显示粗筛提示。
- **FR-005**: 粗筛提示**只是提示，不是判断**：MUST NOT 写入判断记录、MUST NOT 给出"适合投递 / 可以一试 / 需要确认 / 不建议投"等结论、MUST NOT 调用大模型、MUST NOT 占用任何额度（constitution 原则 VII 的解释，见"与 constitution 的关系"）。
- **FR-006**: 粗筛提示 MUST 按计算时的当前画像得出，不作为持久结论保存；画像变化后，下一次列表读取或显示时按新画像重算。
- **FR-007**: 读不到或不可见的信息 MUST NOT 被当作命中：薪资不可见、"面议"、无法解析时不显示"低于薪资底线"；公司行业为空且职位名、公司名都不含任何重点排查行业关键词时不显示"高风险行业"（原则 IV"不知道不能显示成没有"）。
- **FR-008**: 粗筛 MUST NOT 自动隐藏、排序、跳过或点开任何岗位，MUST NOT 向招聘平台发起任何请求。
- **FR-009**: 粗筛只使用列表数据中的职位名、公司行业名称、薪资、城市、岗位标签、技能标签；MUST NOT 读取招聘者姓名、头像、职务、各类令牌字段和行业编号。

**独立职位页被动读取（US2）**

- **FR-010**: 插件 MUST 只在用户自己打开的独立职位页（地址 `/job_detail/<岗位 ID>.html`）加载完成后读取该页，沿用现有的页面变化检测与自动重读机制；MUST NOT 自动打开、在后台打开或刷新任何页面，MUST NOT 额外请求招聘平台。
- **FR-011**: 插件 MUST 从页面上已显示的内容读取：岗位 ID（取自地址）、职位名、薪资、城市、职位描述（岗位详情区的职位描述正文，不含"薪资说明"和"公司介绍"）、公司工商登记名。岗位 ID、职位名、职位描述为必需字段；薪资、城市、公司名可缺，缺失时按现有"不知道"规则如实标注。
- **FR-012**: 必需字段缺失、页面结构变化或地址中没有可识别的岗位 ID 时，插件 MUST 显示"此页暂不支持读取"，MUST NOT 入库、MUST NOT 判断，MUST NOT 退回读取整页文字（原则 V）。
- **FR-013**: 必需字段齐全时，岗位 MUST 按"完整信息"入库（与列表页右侧详情区读到的岗位相同的合并与版本规则），并按现有规则判断（去重、每日额度、过时判断自动更新等全部沿用）。
- **FR-014**: 公司名 MUST NOT 覆盖岗位库中已有的公司名；只有库里没有公司名时，才记为页面上的工商登记全称。
- **FR-015**: 第一版 MUST NOT 读取独立职位页上的公司行业（页面右侧「公司基本信息」栏有行业，但位置未经探测确认）。岗位库已有公司行业（曾在列表页读到）时沿用；没有时判断中公司行业写"未提供"，由大模型按 002 FR-057 根据公司名、职位名和职位描述推断。需要时再用探测插件 0.3 版确认位置，另行修订本条。
- **FR-016**: 插件 MUST NOT 读取独立职位页上的招聘者信息、法定代表人姓名、公司地址，以及相似岗位、推荐岗位列表中的任何内容。
- **FR-017**: 独立职位页的岗位卡片 MUST 与列表页右侧详情区的卡片一致（结论、状态按钮、HR 实际情况、重新判断等）；002 FR-058"点「立即沟通」自动标已投递"本期不扩展到独立职位页（2026-09-29 由 005 FR-009–FR-010 扩展）。
- **FR-018**: 发给大模型的字段 MUST 与现有详情判断相同（职位名、公司名、公司行业、薪资、城市、区域、职位描述），不新增字段；唯一区别是库里原本没有公司名的岗位会送出工商登记全称。按 CLAUDE.md"发往外部模型的内容变更先确认后生效"，用户已于 2026-09-29 确认这一点，实现时无需再次确认。

### Key Entities

- **粗筛提示**：某个列表岗位在当前画像下命中的规则提示，包含岗位 ID、提示类型（高风险行业 / 低于薪资底线 / 命中不接受条件 / 不去的城市）、提示文字（含命中的行业名或词）。只用于显示，不持久保存为判断，不属于任何判断记录。
- **重点排查行业规则**：002 FR-057 的行业名单与同义名（BOSS 公司行业名称），粗筛与大模型判断共用。
- **岗位（沿用）**：公共岗位库中的岗位；本功能新增一个来源（独立职位页），合并与版本规则不变；公司名与公司行业按 FR-014、FR-015 处理。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在设好画像的情况下浏览搜索列表页，粗筛提示与现有列表标记同时出现，不额外增加可感知的等待（列表标记出现后 0.5 秒内显示完毕）。
- **SC-002**: 浏览任意页数的搜索列表页，本机大模型调用记录、每日额度消耗、判断记录的增加量均为 0（由粗筛引起的部分）。
- **SC-003**: 用真实列表页样本核对：命中四类规则的岗位 100% 显示对应提示，未命中的岗位 0 个显示粗筛提示，薪资不可见或"面议"的岗位 0 个显示"低于薪资底线"。
- **SC-004**: 粗筛提示与点开同一岗位后规则排除的结论一致：同一画像下，命中薪资底线、不去的城市、以及职位名命中不接受条件的岗位，点开后 100% 被规则排除为"不建议投"；仅因岗位标签或技能标签命中的岗位不在此列（见 FR-002）。
- **SC-005**: 从聊天页点「查看职位」打开的独立职位页，在标准结构页面上 100% 读取成功并入库、判断；回到聊天页后"当前岗位"区块 100% 显示在库。
- **SC-006**: 结构异常或读不出的独立职位页 100% 显示"此页暂不支持读取"，且岗位库与判断记录增加量为 0。
- **SC-007**: 已在库且有公司名的岗位，打开其独立职位页后公司名被覆盖的数量为 0。
- **SC-008**: 整个功能使用期间，Jet 向招聘平台发出的请求数为 0，自动打开的页面数为 0。

## Assumptions

- 画像字段（最低月薪、不接受条件、不去的城市）与现有规则排除（002，规则版本 r3）相同，本功能不新增画像字段。
- 重点排查行业名单与同义名沿用 002 FR-057 的规则文件；已被真实取值证实的同义名有"餐饮""食品/饮料/烟酒""房地产中介/租赁""房地产开发经营""物业管理"（原推测的"物业服务"改为真实名称"物业管理"，2026-09-29 真实岗位"房地产/厂房(中介)"的公司行业）；"其他消费品""生活服务(O2O)""互联网金融"暂不列入（2026-09-29 用户决定）；保险、汽车、美妆等有样本后再核对。
- 独立职位页读取位置以 0.2 版探测的两个页面为准；实现时用真实页面再验证一次，公司工商登记名是否带标签前缀届时确认。
- "已判断过的岗位不再显示粗筛提示"（判断已包含从严规则与规则排除），用户 2026-09-29 同意。
- 列表卡片标记沿用现有列表标记的位置与样式约束（002 FR-054：不遮挡页面原有信息）。

## 范围外

- 用大模型做列表粗筛（违反 constitution 原则 VII 的"仅列表信息不调用大模型"，本期不做，也不修改宪法）。
- 侧边栏的粗筛汇总。
- 读取独立职位页右侧公司栏的行业（待探测 0.3 版确认后另行修订）。
- 在独立职位页支持"点「立即沟通」自动标已投递"。
- 自动打开、预取或在后台读取任何页面。
