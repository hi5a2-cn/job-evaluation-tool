# Quickstart: 验证岗位信息跨页面联通（第一批）

**Feature**: `005-cross-page-job-link`

---

## 一、前提条件

1. `jet serve` 在后台正常运行（单用户，端口 8000，使用 `127.0.0.1`）；
2. 浏览器插件已在 `chrome://extensions` 重新加载最新代码；
3. 已配对当前插件；
4. BOSS 直聘页面（聊天页、搜索列表页、独立职位页）已刷新。

---

## 二、自动化验证命令

执行以下三组自动化测试与语法校验命令：

### 1. 后端单元与接口测试（pytest）

```bash
uv run --frozen pytest
```

- **预期结果**：全部通过；
- **核心覆盖范围**：
  - `POST /v1/chat/job` 接口幂等性、参数校验（422 空参数拦截）、鉴权（401）；
  - 聊天入库不写 `job_versions`、不写 `job_status`、不触发判断、不调大模型；
  - `job_chat_seen` 针对 `(user_id, job_id)` 的 upsert 行为（首次写入、重复更新 `last_seen_at`）；
  - `src/jet/domain/jobs.py` 中 `current_version_id` 为 NULL 的安全版本补录（列表与详情页）；
  - 岗位库 `all_jobs` 统计口径将 `job_chat_seen` 纳入并集；
  - 岗位条目 `_job_entry` 包含 `seen_in_chat` 布尔字段及 `title` 回退。

### 2. 插件端单元测试（Node.js test runner）

```bash
node --test extension/tests/*.test.js
```

- **预期结果**：全部通过；
- **核心覆盖范围**：
  - `auto-apply.test.js`：`decideAutoApply` 放开 `/job_detail/` 路径、严格核对 URL 岗位 ID 与 004 读取岗位 ID、ka 属性校验、"继续沟通"跳过；
  - `chat-view.test.js`：`isJobInLibrary` 包含 `seen_in_chat` 判定、`formatChatJobStatus` 在库未判断提示文案（"点「查看职位」获取详情并判断"）；
  - `page-summary.test.js`：`buildListMarks` 从 `listJudgements` 提取 `my_status` 并格式化状态标识；
  - `marks-layout.test.js`：`planMarks` 状态胶囊标签与结论/粗筛标签水平并列、互不遮挡布局。

### 3. 原生 JavaScript 静态语法与引用检查

```bash
node --check extension/src/*.js
```

- **预期结果**：全部通过，无语法解析错误。

## 三、真实页面验证要点（用户手动操作）

| 编号 | 验证步骤与操作 | 预期结果 | 对应验收标准 |
|---|---|---|---|
| **Q1** | 打开一个在库岗位的 BOSS 聊天页，展开侧边栏 | 当前岗位卡片顶部展示状态按钮组（收藏/已投递/不考虑），选中态与岗位库一致 | FR-001, SC-001 |
| **Q2** | 在侧边栏点击"不考虑"按钮 | 按钮高亮变为"不考虑"；新开标签页打开岗位库（`myjobs.html`），该岗位状态同步显示为"不考虑" | FR-002, SC-001 |
| **Q3** | 在侧边栏再次点击"不考虑"按钮 | 按钮取消选中，恢复为未设置状态；刷新岗位库，该岗位状态清除 | FR-002 |
| **Q4** | 快速连续切换会话 A → B → A | 侧边栏当前岗位卡片随会话即时刷新，状态选中态严格对应当前会话岗位，不发生串岗与显示错乱 | FR-004, SC-001 |
| **Q5** | 打开搜索列表页（`/web/geek/job`），浏览包含有状态岗位的卡片 | 有状态的岗位卡片在顶部留白行左侧展示对应状态胶囊（"收藏"、"已投递"或"不考虑"）；与卡片上已有的结论标识（如"适合投递"）或粗筛提示（如"粗筛：高风险行业"）水平并列排布，互不遮挡 | FR-005, FR-006, SC-002 |
| **Q6** | 在搜索列表页点开某岗位，在右侧详情区点击状态按钮（如设为"不考虑"） | 保存成功后，同一页面左侧对应卡片的状态胶囊在 1 秒内无感更新，无需手动刷新页面 | FR-007, SC-003 |
| **Q7** | 检查搜索列表中未设置状态的岗位卡片 | 卡片上不展示状态胶囊，仅保留原有结论或粗筛标记；不产生额外网络请求 | FR-008, SC-002 |
| **Q8** | 从聊天页顶部点击「查看职位」打开独立职位页（`/job_detail/<id>.html`），自己点击文字为"立即沟通"的按钮 | 页面右上角弹出约 8 秒的提示框："已标为「已投递」"，右侧附"撤销"按钮；岗位库中该岗位状态变为"已投递"；BOSS 自身的沟通弹窗/流程照常触发不受阻断 | FR-009, SC-004 |
| **Q9** | 在上述 8 秒提示倒计时内点击"撤销" | 状态被撤回，恢复为点击前状态（或未设置）；岗位库同步恢复 | FR-009, SC-004 |
| **Q10** | 在独立职位页遇到按钮文字为"继续沟通"或其他文字并点击 | 插件保持静默，不做任何自动标记与弹窗 | FR-009, SC-004 |
| **Q11** | 找一个此前从未在列表或详情看过的全新 HR 聊天会话并打开 | 侧边栏当前岗位卡片展示该岗位的职位名与公司名，显示状态按钮组与 HR 输入区，并提示："点「查看职位」获取详情并判断"；检查本机判断记录、大模型调用次数与额度，变化量均为 0 | FR-011, FR-012, FR-015, SC-005 |
| **Q12** | 打开「我的岗位库」的"全部岗位"列表 | 该聊天岗位已列入岗位库中（标明"尚未判断"）；点击聊天页顶部「查看职位」打开独立职位页，004 被动读取接管并触发判断；判断完成后回到聊天页，侧边栏显示 Jet 结论，提示语消失 | FR-013, FR-014, FR-016, SC-005, SC-006 |
