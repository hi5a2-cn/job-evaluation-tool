# 页面行为契约（005）

**Feature**: `005-cross-page-job-link` | **Date**: 2026-09-29

本文档规定本功能涉及的四项跨页面联通行为规范，逐项界定其输入、预期输出以及绝对禁止的行为边界（遵循原则 IV、V、VII）。

---

## 契约一：聊天页侧边栏显示与修改投递状态（US1，P1）

### 1. 输入（Inputs）
- 用户在 BOSS 聊天页（`/web/geek/chat`）打开侧边栏，或切换聊天会话；
- 侧边栏通过 `get_chat_job_status` / `fetchChatJobStatus` 取到当前岗位条目（包含 `my_status`）；
- 用户点击当前岗位卡片上的投递状态按钮（"收藏"、"已投递"、"不考虑"）。

### 2. 输出（Outputs）
- **UI 呈现**：当前岗位卡片展示状态按钮组（收藏 / 已投递 / 不考虑）；若当前岗位已有状态，对应按钮处于选中激活态；
- **交互切换**：
  - 点击非选中按钮：立即发送保存请求，按钮组更新为新状态；
  - 再次点击已选中的按钮：取消状态（恢复为未设置）；
  - 保存期间按钮禁用，防止连点与重复提交；
  - 若保存失败：恢复点击前的选中态，并在按钮旁呈现提示文案"保存失败"（约 2 秒后自动消失）；
- **防乱序**：切换会话时，沿用 003 防乱序规则（`isChatJobResponseCurrent`），旧岗位的保存回调不得覆盖新会话卡片；
- **未判断提示**：若该岗位在库但尚未完成判断，卡片如实标明"未判断"，并显示提示原文："点「查看职位」获取详情并判断"（FR-015）。

### 3. 不做什么（What NOT to do）
- **绝不向 BOSS 发起请求**：修改状态只调用本机 Jet 接口，不改变 BOSS 聊天或系统状态；
- **绝不打断正常沟通**：状态修改为后台异步交互，不遮挡、不影响聊天输入与消息收发；
- **绝不未经点击擅自改动**：除非用户亲自点击按钮，绝不自动预设或变更任何投递状态。

## 契约二：搜索列表卡片显示投递状态（US2，P1）

### 1. 输入（Inputs）
- 用户在 BOSS 搜索列表页（`/web/geek/job`）浏览，列表加载完成并触发现有读取流程；
- 服务端响应列表条目中携带已有的个人状态（`my_status`）；
- 用户在同一页面的右侧详情卡片中修改状态（手动改状态、点「立即沟通」自动标记、或点撤销）。

### 2. 输出（Outputs）
- **卡片标记展示**：
  - 对有状态的岗位卡片，在卡片顶部留白行左侧渲染对应状态胶囊标识（"收藏"、"已投递"或"不考虑"）；
  - 无状态的岗位卡片绝对不显示状态胶囊；
- **共存不遮挡（FR-006）**：
  - 已有 Jet 结论标识或粗筛提示保持 004 原位置不动；状态胶囊排在其右侧（间距 4px），没有结论/提示时放在 `rect.left + 8`；两者水平并存、互不遮挡，空间不足时截断状态胶囊文字；
  - 标签只在卡片顶部可见（`space >= 12` 且未被页面顶栏遮挡）时显示，被遮挡时仅保留左侧外沿色条；
- **即时联动更新（FR-007）**：
  - 右侧详情区状态变更成功后，内容脚本在 1 秒内局部更新内存 `list_marks` 并重新触发 `updateMarksPositions()`，同一卡片标识立即更新，无需用户手动刷新页面。

### 3. 不做什么（What NOT to do）
- **绝不触发额外判断**：状态标识仅使用列表查询已返回的数据，绝不因展示状态而向大模型或判断服务发起请求；
- **绝不遮挡职位内容**：严格遵循 FR-054 不遮挡规则，标签绝不侵入职位名称、薪资或公司名称所在的主要内容区域；
- **绝不产生多行折行**：状态标识与结论标识均在单行留白内排布，放不下时结论标签按规则截断，不产生多行错位。

## 契约三：独立职位页「立即沟通」自动标记已投递（US3，P2）

### 1. 输入（Inputs）
- 用户在浏览器中打开独立职位页（URL 匹配 `https://www.zhipin.com/job_detail/<id>.html`）；
- 插件 004 独立职位页被动读取成功，获得可信的当前岗位 ID（`currentJobId`）；
- 用户自己点击页面上的沟通按钮。

### 2. 输出（Outputs）
- **触发判断**：
  - 页面路径必须为 `/job_detail/`（或 `/web/geek/job`）；
  - 必须由 004 读取到有效 `currentJobId`，且该 ID 必须与当前 URL 路径中的岗位 ID 严格一致；
  - 按钮文字经 `trim()` 处理后必须**恰好**为 `"立即沟通"`；
  - 若按钮带有 `ka` 属性，且 `ka` 不包含该岗位 ID，判定为不匹配并跳过；
  - 当前状态已是 `applied` 时跳过；
- **标记与反馈**：
  - 命中上述规则后，内容脚本通过消息向后台 Service Worker 发出 `set_job_status(applied)` 保存请求；
  - 页面右上角弹出约 8 秒的半透明提示条："已标为「已投递」"，右侧附"撤销"按钮；
  - 用户在 8 秒内点击"撤销"：立即恢复为点击前状态（或未设置）；
  - 若保存失败：提示"未能自动标记为已投递"（3 秒后消失），且不进行静默重试。

### 3. 不做什么（What NOT to do）
- **绝不阻止、延迟或代替点击**：事件监听采用 `capture: true, passive: true`，BOSS 自身的沟通弹窗、跳转或即时通信逻辑照常并行执行；
- **绝不误伤其他按钮**：按钮文字为"继续沟通"、"立即投递"或其他文案时绝对不触发；
- **读取失败时绝不标记**：若页面未加载完或结构异常导致 004 读取失败，因无法核对岗位 ID，绝对不盲目标记。

## 契约四：聊天岗位自动被动入库（US4，P2）

### 1. 输入（Inputs）
- 用户在 BOSS 聊天页（`/web/geek/chat`）打开某个会话；
- 插件 MutationObserver 检测到聊天顶部职位条目发生变动（`chat_top_changed`）；
- 后台 Service Worker 在页面 MAIN world 中读到当前活跃会话的岗位 ID（`encrypt_job_id`）及职位名（`title`）。

### 2. 输出（Outputs）
- **被动入库与记录**：
  - 后台异步向本机发起 `POST /v1/chat/job`；
  - 若岗位此前未入库：在 `jobs` 表插入一行记录（`completeness='list_only'`, `current_version_id=NULL`, `company_name=页面公司名`, `first_seen_at/last_seen_at=now`）；
  - 在 `job_chat_seen` 表记录当前用户遇到该岗位的事实及读到的职位名；
  - 岗位库「全部岗位」统计数字与列表同步计入该岗位；
- **侧边栏联动呈现**：
  - 侧边栏当前岗位卡片呈现职位名、公司名、投递状态按钮组、HR 实际情况编辑区；
  - 明确标注"未判断"，并提示："点「查看职位」获取详情并判断"；
- **后续打通**：
  - 当用户在聊天页顶部点击「查看职位」新开标签页时，004 详情读取自动接管，读取完整职位详情、补全版本并触发判断。

### 3. 不做什么（What NOT to do）
- **绝不调用大模型**：聊天岗位入库绝对不调用 DeepSeek 或任何外部模型，不占用每日大模型额度，不增加判断记录；
- **绝不触发规则粗筛**：该岗位信息不完整，不做任何规则粗筛，不计算 `screen_hints`；
- **绝不覆盖已有数据**：若岗位此前已在库（如从搜索列表或详情页入库），绝不修改其已有的职位名、公司名、判断结论与投递状态；
- **绝不强行入库损坏数据**：若页面上读不到岗位 ID 或职位名为空，绝对不写入数据库；
- **绝不在服务故障时无休止重试**：若 Jet 服务未开启或未配对，捕获错误后静默忽略，不重试，不影响用户的正常沟通。
