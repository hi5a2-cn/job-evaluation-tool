## 1. 自动化测试套件

在合入分支前，必须执行以下全量自动化验证命令，保证所有测试全部通过。

### 1.1 Python 后端与 API 测试
```bash
uv run --frozen pytest
```

重点覆盖模块与核心断言：
- `tests/unit/test_migrations.py`:
  - 验证从 v8 迁移至 v9 成功，重建 `resume_slots` 表；
  - 验证旧数据中 `job_types` 完整平滑迁移至 `profile`，`resume_text` 设为 `NULL`；
  - 验证 `user_settings` 新增 `daily_resume_profile_limit` 字段且默认值为 10；
  - 验证 `llm_calls` 表重建后历史调用数据与计费记录 100% 保留；
  - 验证迁移失败时的事务回滚机制与外键一致性（`PRAGMA foreign_key_check`）。
- `tests/unit/test_sanitize.py`:
  - 验证 18 位身份证号码正则准确识别与掩码（`[已隐藏]`）；
  - 验证姓名三来源（`display_name`、上传区 `self_name`、PDF 首行与姓名正则）合并去重与尊称扩展；
  - 验证三来源均无法获取姓名时阻断报错（`SelfNameRequiredError`）；
  - 验证虚构测试数据中姓名、手机号、邮箱、微信 100% 被脱敏，请求体中绝对无明文残留。
- `tests/unit/test_resume_pdf.py`:
  - 使用纯 Python 代码生成的微型虚构文字 PDF，验证 `pypdf` 成功提取全文；
  - 使用无文字/扫描件 PDF 样本，验证文字少于 50 字符时抛出 `NoTextError`；
  - 验证遇到损坏或加密 PDF 时抛出 `PdfInvalidError`；
  - **零落盘安全断言**：断言上传与提取全流程结束后，项目数据目录下没有任何 `.pdf` 文件生成，数据库中没有任何二进制 BLOB 存储。
- `tests/unit/test_resume_quota.py`:
  - 验证 `usage_today`、`remaining_today` 与 `reserve` 对 `purpose='resume_profile'` 的独立计数；
  - 验证画像生成调用只扣减 `daily_resume_profile_limit`，绝对不消耗岗位判断（`daily_llm_limit`）；
  - 验证配额耗尽时 `reserve` 返回 `None`。
- `tests/unit/test_prompt_v6.py`:
  - 验证 `build_resume_instruction` 提示词格式更新为 `- 简历{slot}：{profile}`；
  - 强校验提示词中绝对不包含简历名称、不包含简历原始全文；
  - 验证 `PROMPT_VERSION` 保持 `"v6"` 不变。
- `tests/api/test_resume_routes.py`:
  - 验证 `POST /v1/resumes/upload` 接口鉴权与超过 5MB 文件拦截（413/422）；
  - 验证正常文字 PDF 上传后成功入库 `name`、`resume_text`、`profile` 并返回字符数；
  - 验证额度耗尽（429）或无 Key（409）时，依然降级保存 `name` 与 `resume_text`；
  - 验证 `POST /v1/resumes/{slot}/regenerate` 利用已存文本成功重新生成画像；
  - 验证 `GET /v1/resumes` 仅返回画像与元数据，绝对不泄露 `resume_text` 全文；
  - 验证 `PUT /v1/resumes` 更新名称和画像（≤300字校验）；
  - 验证 `DELETE /v1/resumes/{slot}` 彻底物理删除该行记录。

## 2. 真实页面端到端验证清单 (E2E Checklist)

按照以下真实页面步骤进行手动端到端验证，确保在真实 Chrome 环境下的行为符合设计预期。

### 验证场景 1：在设置页上传一份包含文字的虚构简历 PDF
- **前置条件**：本机 Jet 服务已启动且已配对，DeepSeek API Key 已配置，准备一份包含虚构文本的文字版 PDF（如"李明"，包含教育经历与技术栈）。
- **操作步骤**：
  1. 打开 Chrome 扩展设置页（Options），滚动至"我的简历"卡片；
  2. 观察说明文字是否更新为："上传时，简历文字会在本机去掉姓名、手机号、邮箱等联系方式后发送给 DeepSeek 生成简历画像；之后岗位判断时只发送画像（编号为简历1/2/3，不发送简历名称）。本机只保存提取出的文字和画像，不保存 PDF 文件。"；
  3. 点击"添加简历"，在简历 1 中点击"选择文件"，选中准备好的虚构 PDF 文件；
  4. 观察简历名称是否自动填充为去除 `.pdf` 的文件名；
  5. 点击"上传并生成画像"按钮；
  6. 观察按钮变为加载状态，数秒后返回生成成功的简历画像。
- **预期结果**：
  - 简历画像文本框中展示出精练的画像（包含适合方向与核心亮点，字数 ≤300 字）；
  - 下方字数统计正确显示（如"已输入 185 / 300"）；
  - 检查服务端数据目录，无任何 `.pdf` 临时文件留存。

---

### 验证场景 2：上传扫描件（无文字 PDF）报错拦截
- **操作步骤**：
  1. 准备一份纯图片扫描件 PDF（无法直接选中文本）；
  2. 在设置页简历 2 点击选择该扫描件，点击"上传并生成画像"。
- **预期结果**：
  - 页面弹出/展示明确错误提示："无法读取文字，请上传文字版 PDF"；
  - 大模型请求未触发，大模型每日配额未被消耗；
  - 简历 2 槽位保持原有状态，不保存损坏或无效数据。

---

### 验证场景 3：未填写姓名且未识别出姓名时的阻断提示
- **操作步骤**：
  1. 准备一份正文和首行均完全不包含真实或虚构姓名的纯技术总结 PDF；
  2. 设置页上传区"你的姓名"输入框保持为空；
  3. 点击上传并生成画像。
- **预期结果**：
  - 服务端拦截并返回 422；
  - 界面提示："没有识别出你的姓名，请在上传区填写姓名后重试（只在本机用于去掉姓名）"；
  - 坚决未向 DeepSeek 发起请求。
  - 用户在输入框中填入虚构姓名"王五"后重新点击上传，请求顺利完成并脱敏。

---

### 验证场景 4：手动微调画像并保存
- **操作步骤**：
  1. 针对已生成的画像内容，在文本框中手动追加或修改若干字；
  2. 观察字数统计实时变化；若超过 300 字，字数统计变红且阻断保存；
  3. 调整在 300 字以内后，点击"保存简历"。
- **预期结果**：
  - 提示"已保存"；
  - 刷新设置页，修改后的画像内容完整回显；
  - 服务端未调用大模型（未消耗调用额度）。

---

### 验证场景 5：浏览岗位详情页验证多份简历推荐
- **操作步骤**：
  1. 确保已录入至少 2 份具有画像的简历（例如简历 1 为后端开发画像，简历 2 为数据分析画像）；
  2. 在 BOSS 直聘打开一个技术岗位详情页；
  3. 观察侧边栏或悬浮卡片展示的判断结论。
- **预期结果**：
  - 岗位判断正常完成，结论下方展示"推荐简历：简历 1（理由：...）"；
  - 检查后端抓包或断言日志，发往模型的 Prompt 仅包含 `- 简历1：...` 与 `- 简历2：...`，绝不包含简历名称与简历原始全文；
  - 历史已判断过的岗位不被标记为过时（stale=false）。

---

### 验证场景 6：删除简历彻底清空
- **操作步骤**：
  1. 在设置页点击某份简历的"删除"按钮；
  2. 确认删除操作。
- **预期结果**：
  - 该份简历项从页面立即移除；
  - 查询数据库 `resume_slots` 表，该 slot 记录被完全物理删除；
  - 刷新设置页，该槽位恢复为空位状态。
