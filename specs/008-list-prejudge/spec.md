# Feature Specification: 列表页岗位大模型预判 (008-list-prejudge)

**Feature Branch**: `008-list-prejudge`

**Created**: 2026-09-30

**Status**: Draft

**Input**: 2026-09-30 用户需求（已确认）：
1. 修订 constitution 原则 VII：允许对"只有列表信息"的岗位做大模型预判，但必须标明是"预判"、不写入判断表（judgements）、不当作正式结论，并单独设每日上限（默认每天 20 页，可在设置页改）。按 constitution 的修订规则升版本号（4.0.2 → 5.0.0，MAJOR）。
2. 每一页列表打包成**一次**大模型请求，只用页面已有字段：职位名、公司名、公司行业、薪资、城市（含区）、经验、学历、岗位标签、技能标签，以及用户的画像和用户勾选的从严行业。给每个岗位输出三档之一："值得点开 / 一般 / 可以跳过"加一句理由（≤30字）。
3. 显示在列表卡片上，和正式判断在外观上明显区分；已经有正式判断（status=done 且有结论）的岗位只显示正式判断。点开岗位后照常做正式判断。
4. 不向 BOSS 发任何额外请求，不点击，不滚动，只用页面已加载的数据；翻页或加载更多之后，新出现的岗位再打包预判。

---

## 概述与定位

在用户浏览 BOSS 招聘列表页时，由于尚未点开岗位详情，现有系统只在页面卡片上显示基于关键词/行业的规则粗筛提示（如"从严行业：xx"），用户无法快速了解整体信息（薪资、经验、技能标签、公司行业、背景等）是否综合匹配其画像。

本功能引入**列表页大模型预判**：
- **粗略导向**：仅基于列表页已有的有限信息给出轻量预判（"预判·值得点开 / 预判·一般 / 预判·可跳过"），绝不当作正式结论；
- **严格隔离**：预判数据独立存入 `prejudgements` 表，按用户隔离，与正式判断表（`judgements`）完全无关；
- **批次调用与成本控制**：整页新出现的岗位打包成**单次**大模型请求，每日配额按"页"独立计数（默认每天 20 页，0–200 可配置），与正式判断额度互不挤占，用完即止不排队；
- **视觉区分**：预判卡片标记采用虚线/半透明色条与空心描边标签，鼠标悬停展示理由；正式判断一旦完成，优先显示正式判断。

### 与 Constitution 5.0.0 及主线的关系

- **原则 I（主线优先）**：服务于主线中的"在页面上提醒"环节，帮助用户在浏览列表时决定是否点开岗位详情，不扩展任何自动化打招呼/投递外围功能。
- **原则 II（数据归属从第一天明确）**：预判数据归属于当前用户，存入独立的 `prejudgements` 表，不写入公共岗位库，不写入 `judgements` 表；其他用户看不到预判内容。
- **原则 IV（只读，不向招聘平台发起任何请求）**：插件仅被动读取当前页面已加载的数据（Vue 实例中的字段），不触发任何网络请求、不自动滚动、不翻页、不点击。
- **原则 VII（成本有上限）**：遵循 5.0.0 最新修订：整页打包一次调用；独立配额（默认 20 页/天，可在设置页调整为 0–200）；额度用完当天停止预判，不排队到以后；已有正式判断的岗位不预判；当前画像已预判的岗位直接读缓存不重复调用。
- **原则 VIII（测试与数据安全）**：发送给大模型的字段仅限列表已有字段及画像字段，严禁泄露 HR 实际情况或聊天内容；默认测试不联网、不写真实数据目录；仓库中绝不包含任何用户个人隐私信息。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 列表页浏览时自动获得整页岗位预判 (Priority: P1)

用户在 BOSS 搜索或推荐列表页浏览岗位时，插件读取页面已加载的数据并上报。后端将本页尚未进行正式判断且无当前画像预判的岗位打包成一次大模型调用，快速输出轻量预判结果（"预判·值得点开"、"预判·一般"、"预判·可跳过"）及一句简短理由（≤30字）。插件在卡片左侧呈现虚线/半透明标记，标签为空心描边文字，鼠标悬停在标记上即可查看预判理由，帮助用户一眼决定哪些岗位值得点击查看详情。

**Why this priority**: 这是列表预判的核心交付价值，帮助用户大幅降低筛选时间。

**Independent Test**: 打开包含未判断岗位的列表页（或使用列表数据样本），触发观测上报后，系统发起一次打包预判请求，卡片上显示"预判·值得点开/一般/可跳过"空心标记，鼠标悬停显示理由。

**Acceptance Scenarios**:

1. **Given** 用户打开列表页，页面包含 10 个未判断岗位且额度充足，**When** 列表被动读取完成，**Then** 后端接收到 10 个岗位并打包为 1 次大模型请求，返回 10 条预判结果并写入 `prejudgements` 表，卡片显示对应预判标记。
2. **Given** 列表卡片已渲染预判标记，**When** 鼠标悬停在标记上，**Then** 提示框（tooltip/title）显示预判理由（如"薪资与技术栈匹配，可进一步了解"）。
3. **Given** 页面已存在部分预判结果，**When** 用户向下滚动或点击翻页加载了 15 个新岗位，**Then** 仅对新出现的岗位发起 1 次打包预判请求，已预判的岗位不重复调用大模型。
4. **Given** 本页所有岗位在当前画像下均已在数据库中有预判记录，**When** 用户再次访问该页，**Then** 直接从 `prejudgements` 缓存返回，大模型调用次数为 0。

---

### User Story 2 - 正式判断与预判外观区分及优先级展示 (Priority: P1)

用户在列表页中同时看到未判断岗位与曾经打开过并完成正式判断的岗位。对于已有正式判断（status='done' 且有结论）的岗位，卡片只展示正式判断标记（实线色条、实心标签），绝不发起预判调用，也不展示预判标记。当用户点开一个带有"预判"标记的岗位进入详情页时，系统按既有流程启动后台正式判断；正式判断完成后，卡片标记实时更新为正式判断标记，预判标记退场。

**Why this priority**: 确保正式判断与粗略预判严格区分，防止用户混淆结论权威性，保证主线一致性。

**Acceptance Scenarios**:

1. **Given** 列表中某个岗位已有正式判断（例如 `verdict: "apply"`, status: "done"），**When** 发送列表预判请求，**Then** 服务端跳过该岗位，不加入预判提示词，插件卡片仅显示正式判断的"建议投递"（实心标记）。
2. **Given** 某个岗位目前展示"预判·值得点开"，**When** 用户点击进入岗位详情页，**Then** 系统触发正式判断流程，后台完成后卡片标记立即更新为正式判断结论（如"建议投递"或"可以试试"），预判标记不再显示。
3. **Given** 列表卡片上同时存在正式判断标记和预判标记，**When** 用户视觉对比，**Then** 预判标记呈现虚线/半透明色条与空心描边标签，带有"预判"前缀字样；正式判断为实线色条与实心标签，两类标记在视觉上明显区别。
4. **Given** 某个岗位既无正式判断也无预判，但命中了从严行业或排除规则，**Then** 卡片显示"粗筛：从严行业 · ..."提示标记；其优先级低于预判标记。

---

### User Story 3 - 预判独立每日额度管理与开关 (Priority: P2)

用户在插件设置页查看和调整"列表预判"的每日上限（单位：页，即预判大模型请求次数），可在 0–200 之间设置，默认 20 页。设置页显示今日已用页数与剩余页数。当设为 0 时表示完全关闭列表预判。当每日配额用尽时，服务端返回 `quota_exhausted`，当天不再调用大模型、不排队，插件不弹出错误提示、静默降级展示粗筛提示或无标记。

**Why this priority**: 遵循宪法原则 VII，保障调用成本完全受用户控制，不与其他调用混用。

**Independent Test**: 在设置页将额度改为 1 页，访问两页新列表，第一页成功预判，第二页大模型调用被拦截并返回 `quota_exhausted`，当天调用次数不超限。

**Acceptance Scenarios**:

1. **Given** 用户打开设置页，**When** 滚动至"列表预判"卡片，**Then** 显示当前配置的每日上限输入框（默认 20）、今日已用页数与今日剩余页数。
2. **Given** 用户将每日上限调整为 50 并点击保存，**When** 保存成功，**Then** 数据库 `user_settings.daily_prejudge_limit` 立即更新为 50，并在下次预判时按 50 校验。
3. **Given** 用户将每日上限设为 0，**When** 浏览列表页，**Then** 服务端预占额度返回 None，不调用大模型，列表卡片不展示预判标记。
4. **Given** 今日已调用预判次数达到上限，**When** 用户继续浏览新列表页，**Then** 服务端返回 `{status: "quota_exhausted"}`，不调用大模型、不排队；列表卡片正常显示页面已有信息或粗筛提示，不显示错误弹窗。
5. **Given** 用户修改并保存了求职画像，**When** 保存成功，**Then** 插件清空 `listPrejudge` 与 `listSent` 缓存，新浏览列表时使用新画像重新发起预判。

---

### Edge Cases

- **列表岗位全部已判断**：当整页岗位都已有正式判断（status='done'）时，服务端识别候选岗位为空，直接返回空预判集，大模型调用次数为 0。
- **列表超长（>40条）**：当极端情况下列表加载超过 40 条时，服务端截断仅处理前 40 条，保障提示词上下文长度与单次响应耗时可控。
- **大模型响应格式不合规**：大模型返回内容可能格式错误、缺少某些 id、level 取值非法或 reason 超长。后端需进行严谨校验与截断（reason ≤ 40字），丢弃非法条目，合规条目正常入库，不因部分条目异常导致整页预判失败。
- **未配置 API Key 或无画像**：服务端返回 `no_llm_key` 或 `no_profile` 状态，不调用大模型，不记录失败状态，不阻塞页面正常浏览。
- **网络超时或大模型接口报错**：服务端捕获异常后返回错误状态，不将岗位记录为失败状态（绝不写入 judgements 表），插件保持静默，不影响详情页正式判断。
- **列表滚动频繁触发**：插件端在 `handleSendList` 成功上报并获得新增未发送条目后才触发预判，避免在 DOM 频繁突变时发起重复网络请求。

## Requirements *(mandatory)*

### Functional Requirements

#### 数据库与持久化模型

- **FR-001**: 数据库迁移 v8 MUST 新建 `prejudgements` 表，字段包含 `id`, `user_id`, `job_id`, `level`, `reason`, `profile_id`, `engine`, `llm_call_id`, `created_at`，并设 `UNIQUE(user_id, job_id, profile_id)` 约束；预判数据 MUST 按用户隔离，MUST NOT 写入 `judgements` 表。
- **FR-002**: `user_settings` 表 MUST 新增 `daily_prejudge_limit` 字段，类型为 `INTEGER NOT NULL DEFAULT 20 CHECK(daily_prejudge_limit BETWEEN 0 AND 200)`，单位为页（即预判请求次数）。0 代表关闭。
- **FR-003**: `llm_calls.purpose` 的 CHECK 约束 MUST 扩展加入 `'prejudge'`，迁移过程 MUST 通过重建表方式完整保留现有历史记录。
- **FR-004**: 预判额度 MUST 在 `jet.llm.quota` 中以 `purpose='prejudge'` 单独管理（`usage_today`、`remaining_today`、`reserve`），使用独立列 `daily_prejudge_limit` 计数，MUST NOT 与正式判断（`judge`）或沟通辅助（`assist`）额度混用。

#### 本机服务端 API

- **FR-005**: 服务端 MUST 提供 `POST /v1/prejudge` 接口，受配对鉴权（`require_paired`）保护；请求体接收 `jobs` 列表（最多 40 条），包含 `platform_job_id`, `title`, `company_name`, `company_industry`, `salary_raw`, `city`, `district`, `experience`, `degree`, `job_labels`, `skills`。
- **FR-006**: `POST /v1/prejudge` 处理流程 MUST 遵循：
  1. 仅处理数据库中已存在的岗位（经 `/v1/observations` 先行入库）；
  2. 过滤排除已有该用户有效正式判断（`status='done'` 且有结论）的岗位；
  3. 对当前有效画像已有预判记录的岗位，直接从 `prejudgements` 缓存提取，不调用大模型；
  4. 对剩余未预判岗位，若列表为空则直接返回；若未配置 API Key 或无画像，返回对应状态且不调用大模型；若配额不足（`reserve` 返回 None），返回 `quota_exhausted` 且不调用、不排队；
  5. 剩余岗位打包为一次非思考模型调用（`settings.judge_engine`，默认 `deepseek-flash:no-think`）；
  6. 严格校验大模型输出 JSON 格式（`id` 匹配本批次、`level` 必须为 `open` | `neutral` | `skip`、`reason` 强制截断至 40 字符内），合规数据批量写入 `prejudgements` 表并完成 `llm_calls` 账单结算。
- **FR-007**: 预判提示词模块（`src/jet/llm/prejudge.py`）MUST 明确声明"本判断仅基于列表粗略信息，不构成正式结论"；发送的字段 MUST 严格限制在：职位名、公司名、公司行业、薪资、城市与区县、经验、学历、岗位与技能标签，以及用户的画像和从严行业；MUST NOT 包含 HR 实际情况（`hr_notes`）、聊天记录或个人隐私字段。
- **FR-008**: 服务端 MUST 提供 `GET /v1/prejudge/settings` 与 `PUT /v1/prejudge/settings` 接口，支持读取和更新 `daily_prejudge_limit`（0–200 整数校验），并返回今日已用与今日剩余页数。

#### 浏览器插件功能

- **FR-009**: `page-reader.js` 列表数据提取 MUST 增补 `experience`（映射自 `item.jobExperience`）与 `degree`（映射自 `item.jobDegree`），缺失时置为 `null`；读取逻辑 MUST NOT 发起额外网络请求。
- **FR-010**: `background.js` 在 `handleSendList` 成功后，MUST 对本次新发现且无正式判断的岗位发起单次 `POST /v1/prejudge` 调用；返回的预判数据保存在 `tabState.listPrejudge`（Map 结构）中并触发重新渲染；若额度耗尽当天不再重试。
- **FR-011**: 用户保存画像时，`background.js` MUST 在清空 `listSent` 的同时清空 `listPrejudge` 缓存。
- **FR-012**: `page-summary.js` 的 `buildListMarks` 标记判定优先级 MUST 严格遵循：
  `正式判断 (done 且有结论) > 预判 (prejudge) > 粗筛提示 (hint) > 仅投递状态 (status)`。
- **FR-013**: 预判标记数据结构 MUST 包含 `type: "prejudge"`, `is_prejudge: true`, `verdict_label`（"预判·值得点开" / "预判·一般" / "预判·可跳过"）、`verdict_tone`（`open` / `neutral` / `skip`）、`reason` 与 `stale: false`。
- **FR-014**: `content.js` 与 `marks-layout.js` 渲染预判标记时，MUST 在视觉上明显区分于正式判断：
  - 侧边色条：使用虚线或半透明样式（`border-left: dashed`，`opacity: 0.7`）；
  - 标签外观：使用空心描边小字样式，带有"预判"前缀；
  - 提示信息：鼠标悬停在标记上展示预判理由；
  - 正式判断样式保持原样不变。
- **FR-015**: 设置页 `options.html` 与 `options.js` MUST 增加"列表预判"卡片，提供每日上限（页）配置输入框、保存按钮及今日已用页数展示，0 表示关闭。

---

### Key Entities

- **Prejudgement（列表预判记录）**：独立于正式判断的轻量评估实体，关联用户、岗位与画像版本。包含档位（`open` / `neutral` / `skip`）、简要理由（≤40字）、调用引擎及关联的 `llm_call_id`。
- **PrejudgeQuota（预判每日配额）**：以"页（单次批处理请求）"为单位的每日限额控制模型，独立记录与重置，独立于判断与沟通额度。
- **PrejudgeSettings（预判设置）**：用户级配置项，控制每日允许的最大预判批次数（0–200，默认 20）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 列表页一页岗位（≤40条）在初次浏览时，在额度允许范围内仅触发 1 次大模型网络请求完成整页预判。
- **SC-002**: 已有正式判断的岗位 100% 仅显示正式判断标记，大模型预判请求候选集排除率为 100%。
- **SC-003**: 预判调用的配额消耗与正式判断、沟通辅助配额 100% 隔离，互不挤占。
- **SC-004**: 预判请求发往大模型的字段严格限于规范声明字段，HR 笔记、聊天记录、个人隐私等敏感数据外发次数严格为 0。
- **SC-005**: 每日预判额度用尽后，大模型请求调用数严格为 0，界面不弹窗、不报错，静默降级。
- **SC-006**: 预判标记与正式判断标记在色条（虚线/透明度）与标签（空心描边及前缀）上具备明显的视觉区分度。

## Assumptions & 边界约束

- **网络模型**：预判采用非思考引擎（`deepseek-flash:no-think`），单次处理 20–40 个岗位可在数秒内完成。
- **前端环境**：BOSS 列表页在滚动加载更多时，插件增量获取新节点，仅对新加入 `listSent` 的增量岗位发起预判。
- **范围外**：
  - 自动滚动页面或后台自动化翻页爬取；
  - 针对预判为"值得点开"的岗位自动打招呼或批量投递；
  - 移动端或非 Chrome 浏览器适配。
