## 1. 自动化测试套件

在合入分支前，必须执行以下全量自动化验证命令，保证所有测试全部通过。

### 1.1 Python 后端与 API 测试
```bash
uv run --frozen pytest
```

重点覆盖模块：
- `tests/unit/test_migrations.py`:
  - 验证从 v7 迁移至 v8 成功，新建 `prejudgements` 表；
  - 验证 `user_settings` 新增 `daily_prejudge_limit` 字段且默认值为 20；
  - 验证 `llm_calls` 表重建后历史调用数据与计费记录 100% 保留；
  - 验证迁移失败时的事务回滚机制与外键一致性（`PRAGMA foreign_key_check`）。
- `tests/unit/test_prejudge_quota.py`:
  - 验证 `usage_today`、`remaining_today` 与 `reserve` 对 `purpose='prejudge'` 的独立计数；
  - 验证预判额度耗尽时 `reserve` 返回 `None`，不扣除额度；
  - 验证预判配额与正式判断配额、沟通辅助配额完全隔离，互不干扰。
- `tests/unit/test_prejudge_prompt.py`:
  - 验证提示词系统声明中明确标明“粗略预判，不作为正式结论”；
  - 验证发送的字段严格限于声明的列表已有字段及画像字段（白名单断言）；
  - 强校验提示词中绝对不包含 HR 笔记（`hr_notes`）、聊天记录、简历名称等私密信息；
  - 验证大模型响应 JSON 解析容错能力（合法解析、ID 匹配过滤、非合法 level 丢弃、reason ≤ 40 字截断）。
- `tests/api/test_prejudge_routes.py`:
  - 验证 `POST /v1/prejudge` 鉴权保护（401）；
  - 验证库内不存在的岗位不进行预判；
  - 验证已有正式判断（`status = 'done'`）的岗位直接排除在预判请求之外；
  - 验证当前画像已预判的岗位直接返回缓存，不触发大模型网络请求；
  - 验证整页岗位打包为 1 次请求；
  - 验证 `GET /v1/prejudge/settings` 与 `PUT /v1/prejudge/settings` 契约与 0..200 范围校验。

## 2. 真实页面端到端验证清单 (E2E Checklist)

按照以下真实页面步骤进行手动端到端验证，确保在真实 BOSS 页面上的行为符合设计预期。

### 验证场景 1：真实 BOSS 列表页浏览触发预判
- **前置条件**：本机 Jet 服务已启动且已配对，DeepSeek API Key 已配置，求职画像已填写，`daily_prejudge_limit > 0`。
- **操作步骤**：
  1. 打开 Chrome 浏览器，访问 BOSS 招聘搜索列表页（`https://www.zhipin.com/web/geek/job`）；
  2. 观察页面加载后，插件在列表岗位卡片左侧和标题旁边渲染的标记。
- **预期结果**：
  - 未正式判断的岗位左侧出现**虚线且半透明**的色条；
  - 岗位标题右侧出现**空心描边小字标签**，分别展示 `"预判·值得点开"`（绿色）、`"预判·一般"`（灰色）或 `"预判·可跳过"`（橙色）；
  - 鼠标悬停在空心标签上时，浮现原生提示框（tooltip），显示大模型生成的一句简要理由（≤30字）；
  - 检查服务端日志或网络请求，整页所有未判断岗位仅触发了 1 次大模型请求。

---

### 验证场景 2：翻页与滚动加载更多
- **操作步骤**：
  1. 在列表页向下滚动或点击翻页，加载第二批岗位；
  2. 观察新增岗位的渲染表现。
- **预期结果**：
  - 仅对新出现的岗位发起 1 次大模型打包预判请求；
  - 第一页已预判的岗位不会重复发起大模型请求；
  - 页面无闪烁、无卡顿，标记平滑展示。

---

### 验证场景 3：点开岗位详情后正式判断优先展示
- **操作步骤**：
  1. 在列表页找到一个展示了 `"预判·值得点开"` 的岗位；
  2. 点击该岗位卡片打开岗位详情页（`https://www.zhipin.com/job_detail/<id>.html`）；
  3. 等待后台正式判断完成（卡片浮窗显示正式判断结论，如"建议投递"）；
  4. 切回或刷新列表页，观察该岗位卡片的标记变化。
- **预期结果**：
  - 详情页按原有流程完成正式判断；
  - 列表页该岗位的标记立即变为**实线实心背景**的正式判断标签（如"建议投递"），带有"预判"字样的空心虚线标记彻底消失；
  - 再次访问列表页，该岗位绝不会再次被纳入预判候选集。

---

### 验证场景 4：设置页每日上限修改与额度用尽
- **操作步骤**：
  1. 打开插件设置页，在"列表预判"卡片中将"每日上限"调整为 `1` 页，点击保存；
  2. 访问列表页，预判第 1 页岗位（消耗 1 页额度）；
  3. 打开第二页未判断的列表岗位；
  4. 观察页面响应与控制台表现。
- **预期结果**：
  - 第 1 页成功展示预判标记；
  - 设置页显示“今日已用：1 页，今日剩余：0 页”；
  - 打开第 2 页时，服务端返回 `status: "quota_exhausted"`，大模型请求次数为 0；
  - 页面不弹出任何报错窗口，未预判岗位正常展示页面原有内容或粗筛提示，浏览流程不受任何阻碍。

---

### 验证场景 5：修改画像后预判缓存清空
- **操作步骤**：
  1. 在设置页修改求职画像（例如修改期望方向或核心技能），点击"保存画像"；
  2. 重新访问此前已预判过的列表页。
- **预期结果**：
  - 插件端 `tabState.listPrejudge` 与 `listSent` 缓存已被清空；
  - 岗位按新画像发起新的打包预判，卡片刷新为与新画像匹配的最新预判标记。
