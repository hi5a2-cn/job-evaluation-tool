# Jet

Jet 是面向个人求职者的本地优先 AI 求职助手：一个 Chrome 插件加一个跑在你自己电脑上的服务。浏览 BOSS 直聘时，它帮你判断岗位值不值得投、该投哪份简历，并在和 HR 聊天时给出沟通建议。岗位、简历和聊天记录都存在你自己的电脑上。

- **会发给大模型（DeepSeek）的内容**：只有下面这些内容会用你自己的 API Key 发给 DeepSeek，其余数据都只存在本机。
  - 判断岗位时：岗位信息（职位名、公司、薪资、地点、职位描述等）、你在画像里同意发送的求职偏好、勾选的从严行业、简历画像；
  - 生成简历画像时：本机去掉姓名、手机号、邮箱等之后的简历正文；
  - 使用沟通助手时：本机脱敏后的聊天内容，首次使用前需要你在侧边栏明确同意。
  详见下文「我的简历与从严行业」和「HR 沟通助手」两节。
- **目前的限制**：只支持 macOS 和 Chrome；大模型只支持 DeepSeek，需要你自己的 API Key（按用量付费）。

## 快速上手

### 安装步骤（macOS）

如果你是直接使用（不需要修改代码），推荐使用此一键安装方式（**Windows 暂不支持**）：

1. **下载**：在本项目 GitHub 页面右侧的 **Releases** 里下载最新版本的源码压缩包（Source code (zip)）。
2. **解压到一个固定位置**：解压到一个固定位置（例如“文稿/jet”），之后不要移动；移动后需重新运行脚本。
3. **运行安装脚本**：打开“终端”（Terminal）应用，运行：
   ```bash
   bash "<解压目录>/scripts/install-macos.sh"
   ```
   （说明：可以先在终端输入 `bash `，然后直接把脚本拖进终端窗口）。脚本会检查系统与 `uv` 工具、配置后台服务并进行健康检查。如未安装 `uv`，按终端提示安装后重新打开终端再运行本脚本即可。
4. **按脚本最后的提示加载插件并配对**：
   - 打开 Chrome 浏览器，访问 `chrome://extensions`，开启右上角“开发者模式”；
   - 点击左上角“加载已解压的扩展程序”，选择 `<解压目录>/extension`；
   - 在终端进入解压目录后运行 `uv run --frozen jet pair` 获取 6 位配对码；
   - 打开插件设置页（在扩展卡片中点“选项”或点击侧边栏右上角设置图标），填入配对码完成配对。
5. **在设置页填写 DeepSeek API Key 并测试连接**：
   - 打开 Jet 设置页，在“DeepSeek API Key”区域输入你的 API Key；
   - 点击“测试连接”，确认连接成功后点击“保存”。

**卸载**：运行 `scripts/uninstall-macos.sh`（即 `bash "<解压目录>/scripts/uninstall-macos.sh"`）。

### 1. 安装依赖

```bash
uv sync
```

### 2. 启动服务

```bash
uv run jet serve
```

首次运行或版本升级时，如果检测到旧结构数据库，Jet 会自动将数据库迁移至最新版本，并在数据目录下保留完整备份文件（格式为 `jet.db.bak-<UTC时间戳>-v<旧版本>`）。

#### 后台运行（macOS LaunchAgent）

在 macOS 上用 `scripts/install-macos.sh` 安装后台服务（见上文"给朋友的安装步骤"，开发者同样适用）：服务由 LaunchAgent `local.jet.serve` 管理，登录后自动启动，意外退出（退出码非 0）10 秒后自动重启，日志追加写到 `~/Library/Logs/jet/serve.log`。服务运行的是仓库当前签出的代码，切换分支或更新代码后要重启才生效；移动了仓库目录则重新运行安装脚本。

**日常命令**：

```bash
# 重启（改了服务端代码后用）：launchd 先正常停止、再立即启动
launchctl kickstart -k gui/$(id -u)/local.jet.serve

# 查看状态（只读）：是否在运行、进程号、上次退出码，并做健康检查
launchctl print gui/$(id -u)/local.jet.serve | grep -E 'state|pid|last exit'; curl -s http://127.0.0.1:47615/v1/health

# 查看日志（持续查看改用 tail -f，Ctrl+C 退出）
tail -n 100 ~/Library/Logs/jet/serve.log

# 卸载（停止并移除服务，不删除数据与日志）
bash scripts/uninstall-macos.sh
```

- **反复重启时先停下**：如果查看状态时 `last exit code` 一直是非 0 且进程号不断变化（例如端口被占用、环境出错），launchd 会每 10 秒重启一次、日志不断增长。先运行卸载脚本停下，看日志找原因，修好后再运行安装脚本。
- **退出码 143 是正常的**：`kickstart -k` 与卸载用 TERM 信号停止服务，服务正常退出后退出码显示为 143，不会触发自动重启。
- **不要用 `kill -9`**：`jet serve` 正常退出时会删除数据目录里的 `admin.secret`；`kill -9` 强杀不会执行这一步，文件会残留。launchctl 的停止与重启都是正常退出。
- **不要同时用其他方式后台启动**：例如 `nohup uv run jet serve &`，会随启动它的程序退出而停止，且与 LaunchAgent 争抢端口 47615。
- **日志内容**：Jet 自己的日志只记方法、路径、状态码、耗时（有敏感信息过滤）；uvicorn 访问日志会带查询参数（例如岗位库搜索词、岗位编号）。都不记录聊天内容或话术。日志是追加写入、不会自动清理，太大时先停服务再清空该文件。

### 3. 配对浏览器插件

在终端运行以下命令获取一次性 6 位配对码（5 分钟有效）：

```bash
uv run jet pair
```

在 Chrome 中加载插件后，打开插件设置页填入该配对码完成配对。

> **重新加载插件后，需要刷新已打开的 BOSS 页面。** 在 `chrome://extensions` 刷新 Jet（或更新代码后重新加载）时，已经打开的 BOSS 标签页里还是旧的插件脚本，不会读取、入库或显示卡片；刷新一下这些页面即可。更新了 Jet 的 Python 代码后，也要重启 `jet serve`。

### 4. 查看统计

```bash
uv run jet stats
```

## 列表页粗筛、预判与独立职位页

- **搜索列表页粗筛提示**：按画像和重点排查行业在未判断的岗位卡片上显示灰蓝色「粗筛：…」提示，只是提示、不调大模型、不花额度，鼠标悬停看全部；保存画像后已打开的列表页自动更新提示。
- **列表页预判**：在搜索列表页，新出现的岗位按页打包，用列表上已有的信息（职位名、公司、行业、薪资、城市、经验、学历、标签）加上画像和勾选的从严行业，调用一次大模型给出「预判·值得点开 / 预判·一般 / 预判·可跳过」，用虚线样式显示在卡片上，悬停看理由。预判只是提示，不写入正式判断，不占判断额度，单独计数（默认每天 20 页，设置页可改）；点开岗位后照常做正式判断，有正式判断的岗位只显示正式判断。
- **独立职位页读取**：独立职位页（如从聊天页点「查看职位」打开）会被读取、入库并判断，读不出时显示「此页暂不支持读取」。

## 岗位信息跨页面联通

同一个岗位的投递状态在各处是同一份，任何一处修改，其他地方都看到新状态（其他已打开的标签页在刷新或重新查询后更新）。

- **聊天页侧边栏改状态**：当前岗位卡片有「收藏 / 已投递 / 不考虑」按钮，再点一次取消，规则与岗位库、详情卡片相同。
- **列表卡片显示状态**：搜索列表页中设过状态的岗位卡片显示状态标识，排在 Jet 结论或粗筛提示右侧、不遮挡；在右侧详情区改状态后，同页卡片标识即时更新。
- **独立职位页自动标已投递**：在独立职位页自己点「立即沟通」，与搜索列表页一样自动标记已投递，约 8 秒内可撤销；相似岗位、推荐岗位区域里的按钮不处理。
- **聊天中的岗位入库**：打开聊天时，Jet 在本机记下该岗位（只存岗位 ID、职位名、公司名），计入岗位库「全部岗位」，可以设状态、记 HR 实际情况；不判断、不调大模型、不占额度、不设状态。未判断时侧边栏提示「点「查看职位」获取详情并判断」。发给外部模型的内容没有变化。

## 我的简历与从严行业（设置页）

两项都是每个用户自己的设置，存在本机数据库，仓库里不写任何个人内容。

- **我的简历**：在设置页「我的简历」上传最多 3 份 PDF（每份不超过 5MB），简历名称默认取文件名，可以改。上传和重新生成画像前要填你的姓名，只在本机用来去掉姓名，不发送，也不保存。
- **简历画像**：上传后，本机先提取 PDF 文字，去掉姓名、手机号、邮箱、微信、身份证号等，再把**脱敏后的简历正文**发给 DeepSeek，生成一段不超过 300 字的「简历画像」（适合方向和几条亮点），可以手动修改。本机只保存提取出的文字和画像，不保存 PDF 文件；删除简历时一起删掉。扫描件读不出文字时会提示，不会发送。生成画像每天最多 10 次，不占判断额度。
- **判断时建议投哪份**：有 2 份以上画像时，判断请求里会附上各份简历的画像（只用「简历1/2/3」编号，不发简历名称），大模型在同一次调用里多给一项「建议投第几份 + 一句理由」，不增加调用次数。
- **显示**：岗位卡片和侧边栏「当前岗位」显示"建议投：<简历名称>"，悬停或点击看理由；结论为"不建议投"、规则判断、未完成或没有建议时不显示。聊天中 HR 发来索要简历的请求卡片时，侧边栏突出显示这条建议。只做提示，不自动发送或选择简历。
- **从严行业**：`src/jet/llm/prompts/strict_industry_rules.json` 只放通用资料（可选行业、同义名、关键词）；在设置页"从严行业"勾选要从严把关的行业，默认都不勾。列表页"高风险行业"粗筛提示和判断提示词只按勾选的行业处理。勾选的行业会随判断发给 DeepSeek。
- **销售从严（提示词 v10 起）**：画像的「不接受关键词」里有一项含「销售」时，销售与客户对接成分为「高」的岗位一律判为「不建议投」；没写「销售」的用户，大模型仍会识别销售成分，但不强制改判。

## 判断规则的版本

判断用的提示词按版本演进，当前默认版本和所有版本登记在 `src/jet/llm/versions.py`（版本表）。近几个版本的主要变化：

- **v7**：经验门槛规则（硬性要求 1 年以内或只写「有相关经验」可以一试，2 年需要确认，3 年以上或要求带团队才可仅因经验判不建议投）。
- **v8**：销售成分从严（v10 起改为只对不接受销售的用户生效）。
- **v9**：判断时附上 BOSS 页面上的「经验要求」「学历要求」标签，并按标签判断硬性门槛。
- **v10**：销售从严按画像生效（见上一节）。

**旧判断**：版本号低于「过时基线」（同样在版本表里）的大模型判断，会标为「判断方式已更新」，再次打开这个岗位时自动重判（花额度）。升级默认版本时基线不一定跟着提：v10 上线时基线留在 v9，v9 的判断不会重判。改简历或从严行业不会让已有判断过时。

## HR 沟通助手

在 BOSS 聊天页打开 Chrome 侧边栏，Jet 沟通助手提供针对当前会话的沟通辅助：

### 功能简介

- **智能建议**：根据当前岗位的 Jet 判断结论、HR 实际情况（如有）以及用户在设置页维护的「我的经历素材」，自动识别沟通阶段并生成 2 个不同语气版本的话术建议（开场白或建议回复，每条 ≤ 50 字）以及最多 3 个建议问 HR 的问题。
- **纯辅助定位**：只生成建议供用户手动复制，**绝不自动填入输入框，绝不自动代发消息**。
- **隐私脱敏与知情同意**：发送前在本地对双方姓名、称呼、电话、微信号、邮箱进行规则脱敏，HR 实际情况发送前会脱敏；画像里填了「目前所在城市」时也会发送；首次使用必须在侧边栏明确同意发送的字段清单并查看只读脱敏预览（当前同意字段版本为 3，明确告知打开聊天会自动发送），发送内容变化时需要重新同意；可在设置页随时撤回同意。
- **自动生成与缓存**：在设置页开启「打开聊天自动生成」（默认开启）时，打开聊天自动触发建议生成；同一聊天按「岗位 ID + 最后一条消息」在侧边栏内存中缓存，切回且无新消息时直接回显缓存（不调用大模型、不占用额度）；可在设置页关闭自动生成，关闭后仅在点击「生成沟通建议」按钮时触发。
- **切换识别保护**：在 BOSS 中切换聊天时，侧边栏立即遮盖当前内容并显示「正在识别当前聊天…」，确认新岗位 ID 后再更新内容，防止串会话误复制；复制话术前再次核验岗位 ID。
- **无判断岗位支持**：当前岗位不在岗位库或未判断时，侧边栏显眼标注「这个岗位没有 Jet 判断」，依然基于已加载消息生成建议并主动附带确认岗位性质的问题。

### 工具栏图标与侧边栏

- **工具栏图标打开侧边栏**：点击浏览器工具栏上的 Jet 图标直接唤起 Chrome 侧边栏（基于 Chrome 114+ 提供的 `sidePanel` API），不再直接打开新标签页。
- **我的岗位库入口**：在侧边栏提供「我的岗位库」按钮，点击在新标签页中打开岗位库；设置页中亦保留岗位库入口链接。

### 聊天页「当前岗位」卡片

- 侧边栏「当前岗位」卡片展示该岗位在公共岗位库中的 Jet 判断结论与 HR 实际情况。打开聊天时会按上面的「聊天中的岗位入库」记下这个岗位；只有读不到岗位 ID 或职位名、没能记下时，才提示「岗位库里没有这个岗位。在 BOSS 搜索列表里看到它时，Jet 会记录并判断」。这张卡片本身不改变岗位状态、不触发大模型判断。
- 支持在卡片内就地编辑 HR 实际情况并自动保存；但**不能在聊天页清空**，输入为空时不保存并提示「清空请到岗位卡片操作」（服务端接口 `PUT /v1/jobs/{platform_job_id}/hr-note` 携带 `source='chat_sidebar'`，对空内容提交拦截并返回 422 `empty_not_allowed`）。

## 我的岗位库改版

独立标签页「我的岗位库」（`myjobs.html`）支持全面管理与高效整理入库岗位，入口位于侧边栏「我的岗位库」按钮及设置页：

### 视图与筛选

- **「全部岗位」标签**：位于标签栏最前面，范围涵盖所有「有状态 ∪ 判断过 ∪ 记过 HR 实际情况」的岗位去重并集，鼠标悬停提示「有状态、判断过或记过 HR 说的话的岗位」；默认仍优先选中「已标记」（无标记时选中「最近看过」）。
- **「只看有 HR 记录」筛选**：勾选框可与任意标签叠加，仅展示已记录 HR 实际情况的岗位；各标签旁的计数实时联动更新为对应状态下有 HR 记录的岗位数。
- **按最近更新时间排序**：列表与搜索结果默认按最近更新时间（状态变化、HR 实际情况保存、打开详情页、最新判断时间中最晚者）倒序排列。

### 岗位库搜索

- 顶部提供搜索框，由本机 Jet 服务端在当前选中标签与筛选范围内进行 SQLite `LIKE` 搜索（英文字母不区分大小写，自动对 `%` 与 `_` 进行转义）。
- 搜索匹配字段覆盖：**职位名（包含该岗位的所有历史版本）**、**公司名**、**HR 实际情况**。
- 单次最多加载 200 条；当匹配结果超过 200 条时，列表上方明确提示「只显示了前 200 条，共 N 条」。

### 行内修改状态与原位标注

- 在列表中可直接点击状态按钮（收藏 / 已投递 / 不考虑 / 取消状态）修改岗位状态。
- 修改后**该行留在原位不跳动**，方便连续整理：
  - 在具体状态标签（收藏/已投递/不考虑）下改为其他状态，原位标注「已改为 X，切换标签或刷新后移出本列表」；
  - 点击「取消状态」按钮时，原位标注「已取消状态，切换标签或刷新后移出本列表」；
  - 改回原状态时，标注自动消失；
  - 切换标签或刷新页面后，岗位按新状态重新归类移出；
  - 「全部岗位」与「最近看过」标签下改状态不移出、不展示标注；「已标记」标签下不同状态互换不移出、不展示标注（仅取消状态展示移出标注）。

### HR 实际情况展示与自动保存

- **两行展示与展开**：每行直接展示 HR 告知的实际情况，最多显示两行并自适应省略截断，实际超出两行时显示「展开」按钮（支持点击展开全文），无记录时显示「未记录」。
- **自动保存机制**：点击「修改」展开编辑框，停止输入约 1 秒或输入框失焦时自动触发保存，界面提示「保存中...」、「已自动保存」或「保存失败」。
- **空内容不保存与清空限制**：
  - 岗位库与侧边栏：内容经 `strip()` 为空时不自动保存，点击「完成」提示「清空请到岗位卡片操作」，防止误删（服务端拒绝空提交）；
  - 岗位卡片（BOSS 页面悬浮卡片）：内容为空时不自动保存，提示「内容为空不会自动保存；要清空请点「清空」」；要清空必须显式点击「清空」按钮。

## 配置说明

Jet 的真实配置文件 `.env` 应当放置在用户数据目录中（默认位置为 `~/Library/Application Support/Jet/.env`），**严禁将包含真实 API Key 的 `.env` 提交到 Git 仓库**。

所有配置项、默认值和说明见仓库根目录的 [`.env.example`](.env.example)，需要哪项就把那一行抄进数据目录的 `.env`；不写的项用默认值。常用的几项：

```bash
JET_PORT=47615
# 每日上限：岗位判断（含复核），默认 150
JET_DAILY_LLM_LIMIT=150
# 每日上限：沟通建议生成，默认 50
JET_DAILY_ASSIST_LIMIT=50
# 复核开关：1 开启（默认），0 关闭
JET_REVIEW_ENABLED=1
```

- **API Key**：一般在设置页填写，保存在数据目录的 `llm_api_key` 文件里；`.env` 里的 `JET_LLM_API_KEY` 只在没有这个文件时才用。
- **注释**：可以单独成行，也可以写在值后面（值和 `#` 之间要有空格）；值留空等于没写，用默认值。
- **提示词版本**：一般不要设置 `JET_PROMPT_VERSION`，留空就用当前默认版本（定义在 `src/jet/llm/versions.py`）；写了不存在的版本号时 `jet serve` 会启动失败并列出可用版本。
- **列表页预判的每日上限**在设置页里改（默认每天 20 页）；简历画像生成固定每天最多 10 次。两者都不在 `.env` 里。
- 改完 `.env` 后重启 `jet serve` 生效。

### 调整每日沟通建议生成上限（JET_DAILY_ASSIST_LIMIT）

每日沟通建议生成调用上限默认 50 次。可在数据目录的 `.env`（`~/Library/Application Support/Jet/.env`）中配置：

```bash
JET_DAILY_ASSIST_LIMIT=50
```

- **默认值**：`50`（合法取值范围为 `0–500` 的整数；设为 0 时当天不能生成沟通建议，侧边栏提示「今日生成次数已用完」）。
- **出处与生效机制**：
  - 读取与范围校验：`src/jet/config.py`（设定默认值 `daily_assist_limit: int = 50`，在 `load_settings()` 中读取环境变量/`.env` 并严格校验 `0 <= daily_assist_limit <= 500`）。
  - 写入数据库：`src/jet/api/app.py`（在应用启动生命周期 `lifespan` 中执行 `UPDATE user_settings SET daily_llm_limit = ?, daily_assist_limit = ? WHERE user_id = 'me'`，将配置值同步写入 SQLite 数据库的 `user_settings` 表）。
  - 额度查询与预占：`src/jet/llm/quota.py`（`remaining_today` 与 `reserve` 在每次请求时查询 `user_settings.daily_assist_limit`，按本机时区统计当天已计费调用并严格拦截超额请求）。
  - 生效方式：在数据目录 `.env` 中修改 `JET_DAILY_ASSIST_LIMIT` 后，重启 `jet serve` 即可生效。

## 评测命令（US7）

在插件卡片上对岗位进行事实与结论标注后，可使用评测命令对比不同提示词与模型组合的表现（A 固定用提示词 v1；B 关思考、C 开思考，两者都用当前默认的提示词版本。原来的组合 D「TypeSafe Jev」已删除）：

### 运行评测

```bash
# 默认评测所有组合 A, B, C
uv run jet eval run

# 指定组合与调用上限
uv run jet eval run --variants B,C --max-calls 300
```

评测结果以 JSON 格式保存在数据目录下的 `evals/<运行ID>.json`，并在终端输出对齐的汇总对比表。评测调用单独计数，不占用每日日常判断额度。

### 查看评测报告

```bash
# 查看最近一次评测报告
uv run jet eval report

# 查看指定运行 ID 的报告
uv run jet eval report 20260924T153000Z
```

### 导出岗位供参考标注

```bash
uv run jet eval export-jobs --out ~/Library/Application\ Support/Jet/evals/jobs_for_label.json --limit 100
```

导出已入库的完整岗位详情、HR 说的实际情况，以及画像中用户同意发送的字段（我的背景、工作内容偏好、城市、最低月薪、不接受关键词）、分类体系和任务说明，供外部大模型生成参考标注。导出文件含职位描述与个人画像，请放在数据目录里，**不要放进仓库**；发给外部模型前需用户明确同意。

### 导入模型参考标注

```bash
uv run jet eval import-reference ~/Library/Application\ Support/Jet/evals/reference_labels.json --source model:gemini-3.8-flash-high
```

逐条校验并导入模型生成的参考标注。评测时，参考答案按字段优先采用用户手动标注；若用户未标注该字段，则采用模型参考标注，并在评测报告中注明答案来源构成及“模型参考标注，非人工”提示。

```bash
uv run pytest -q
```

```bash
cd extension && npm install
```

```bash
node --test extension/tests/*.test.js
```

### 调整每日判断额度

每日判断额度（含复核）默认 150 次。要改的话，在数据目录的 `.env`（`~/Library/Application Support/Jet/.env`）里加一行或修改：

```
JET_DAILY_LLM_LIMIT=200
```

取值 0–500（0 表示只用规则、不调用大模型），保存后重启 `jet serve` 生效。
